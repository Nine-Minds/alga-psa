# Outlook ticket-created confirmation

The stock `ticket-created-client` template omits its description box and text
label when `email_metadata.messageId` is truthy. Other tickets retain the
description. The shared context supplies the flag; threading headers and the
internal `ticket-created` template are unchanged.

Migration `20261117033448_ticket_created_client_omit_email_description.cjs`
re-seeds all stock translations with the existing upsert helper. It does not
update customized copies in `tenant_email_templates`. The migration is
forward-only and has not been applied to the shared dev database.

## Automated checks

- 65 tests passed across `ticketCreatedClientEmail.test.ts`,
  `templateProcessors.test.ts`, and `templateLocaleParity.test.ts`.
- The new 45 cases build the real summary context and render HTML and text
  through the production template processor for all nine locales. They cover
  a message ID, absent/null metadata, metadata without a message ID, and an
  empty message ID. They check description presence, the absence of an empty
  box or orphan text label, and the retained ticket details and portal link.
- Timezone, locale, country, portal-domain resolution, and the connection
  factory are mocked in the unit tests. No emails are sent.
- Migration lint: zero violations. Both changed CommonJS files pass
  `node --check`.
- Full server typecheck passed with
  `NODE_OPTIONS=--max-old-space-size=16384 npm run typecheck --workspace=server`.
  The initial run exhausted Node's default 4 GB heap.
- The local signin route on port 3808 returned HTTP 200 after the change.
