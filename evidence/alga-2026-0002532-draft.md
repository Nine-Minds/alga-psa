# Outlook ticket-created confirmation

Email-origin ticket confirmations omit the description in the stock
`ticket-created-client` HTML and text templates. The summary context derives
`fromEmail` from `Boolean(ticket.email_metadata?.messageId)`. The client audience
allowlist now retains that flag through `projectTicketEmailContext` to rendering.
Other tickets retain the description. Threading headers, the internal
`ticket-created` template, and other notification templates are unchanged.

No plan was attached. The mitigation repairs the projection failure found in the
smoke test of `defbe3214b`; that revision's template-only tests missed the failure.

## Automated checks

- Before the allowlist repair, all 45 confirmation tests failed at the new client
  projection assertion: `fromEmail` was missing for both true and false inputs.
- After the repair, 92 tests passed across `ticketCreatedClientEmail.test.ts`,
  `ticketEmailAudience.test.ts`, `templateProcessors.test.ts`, and
  `templateLocaleParity.test.ts`.
- The 45 confirmation cases build the production summary context, apply the
  production client projection, assert the boolean survives, and render that
  projected context in all nine locales. They cover an inbound message ID,
  absent/null metadata, metadata without a message ID, and an empty message ID.
  They check description presence or omission, the absence of an empty box or
  orphan label, and retained details and portal link. Environment and connection
  helpers are mocked; the projection and renderer are not.
- Full server typecheck passed with
  `NODE_OPTIONS=--max-old-space-size=16384 npm run typecheck --workspace=server`.
- Port 3808 serves this worktree. The card-owned dev service was restarted before
  the live inbound check to reload its subscriber.
