## Evidence limits

The browser network artifact is capped at 100 returned events out of 1000 and has no initiator, redirect-chain, response-header, or response-body fields. It contains one `Document` event, while the service log contains repeated successful `/auth/msp/signin` requests. The service log does not timestamp each line; its order can be correlated with the service lifetime and browser recording window, not precisely joined to each browser event. In particular, a Next streamed redirect can be delivered with HTTP 200, so status alone cannot exclude a redirect embedded in HTML/RSC. Console events show auth rejection warnings and i18n/PostHog warnings, but no captured browser errors that identify a reload initiator.

## Capture on the next authorized live run

Instrument both fresh tabs before navigating, and keep the capture running until at least 30 seconds of stable sign-in UI or a repeated navigation is observed. Use a Playwright Chromium CDP session (or the equivalent Electron DevTools Protocol session for the card browser); `alga-dev browser-get-network` alone does not expose the required fields.

1. Enable CDP `Network`, `Page`, `Runtime`, and `Log` domains before `Page.navigate`. Save every event as newline-delimited JSON with wall-clock UTC and monotonic time, tab/pane ID, frame ID, loader ID, request ID, and URL. Redact cookie values, authorization headers, credentials, and tokens before persisting artifacts.
2. For every `Network.requestWillBeSent`, persist `initiator`, `documentURL`, `frameId`, `loaderId`, `type`, request method/headers (redacted), and `redirectResponse` when present. `redirectResponse` is the redirect-chain evidence that a final 200 request log cannot supply.
3. For each `Network.responseReceived`, persist status, headers, MIME type, resource type, frame/loader IDs, and request ID. On `Network.loadingFinished`, call `Network.getResponseBody` for document and RSC/fetch responses and save the body after redacting secrets. Inspect document HTML for a streamed `<meta http-equiv="refresh">`; inspect RSC responses for Next redirect markers such as `NEXT_REDIRECT`. Preserve the original bytes in a restricted local artifact if redaction would destroy diagnostic value; do not include credentials or session tokens in the report.
4. Record `Page.frameNavigated`, `Page.navigatedWithinDocument`, `Page.lifecycleEvent`, `Network.loadingFailed`, and `Runtime.exceptionThrown`. This separates browser-initiated full navigation, Next client navigation, failed requests, and JS-triggered location changes.
5. Record `Network.webSocketCreated`, `Network.webSocketWillSendHandshakeRequest`, `Network.webSocketHandshakeResponseReceived`, `Network.webSocketFrameReceived`, `Network.webSocketFrameSent`, `Network.webSocketFrameError`, and `Network.webSocketClosed`, including HMR URL, request ID, response status/headers, frame opcode/payload (redacted), and close timestamp. If close code/reason is needed, also attach a browser-level WebSocket close listener or capture it at the proxy; CDP's close event does not provide those fields. Correlate HMR close/reconnect times against navigation loader IDs; do not assume one caused the other.
6. At the same time, preserve the app service log from before navigation through after the loop, plus process start/stop metadata and filesystem watcher/compiler messages. Add UTC timestamps to log records at collection time if the server logger does not provide them. Keep both tabs' event streams separate and mark the exact first input attempt and any form submission.
7. First reproduce without typing credentials. Once a fresh tab demonstrates a stable document and stable HMR connection, proceed with the approved sign-in credentials and smoke plan. If navigation repeats, stop before changing authorization fixtures; diagnose the navigation first.

Minimum deliverables are the redacted per-tab CDP event streams, response-body extracts for every signin document/RSC request, the matching service log and process metadata, and a short event table linking each navigation to its initiator/redirect chain and nearest HMR events. Only then choose a source repair and add behavioral regression coverage for that demonstrated mechanism.
