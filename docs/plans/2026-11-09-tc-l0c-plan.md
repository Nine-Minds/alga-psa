### 2.3 Owner adapter registry (the general mechanism that makes "any owning record" true)

- **New:** `packages/conversations/src/files/owners.ts`, with
  `registerConversationFileOwner(ownerType, { canRead(trx, actor, ownerId), canWrite(trx, actor, ownerId), onOwnerDeleted? })`.
  It has a process-global registry (the same `globalThis[Symbol.for(...)]` pattern as `capability.ts`).
  - An unknown `owner_type` fails closed with `FILE_NOT_FOUND`.
  - Cross-owner copy requires `canRead(source owner)` **and** `canWrite(destination owner)`.
  - Every read and write first scopes by `tenant` through `tenantDb(trx, tenant)`, so a cross-tenant id never resolves.
- **Replaces (in design, not in code):** the reference hard-wired `withNamedTicketConversation` + co-managed session checks
  into `namedConversationPublicationFiles.ts`. Here the domain authority is supplied by the owner adapter.
- **Does not ship:** a `ticket` owner (L1, `packages/tickets`), a co-managed owner (later convergence), or an
  opportunity/project owner (card a132b865). Tests register a synthetic owner type.

### 2.5 Operation-scoped publication copies (prepared → published | abandoned)

- **Reference:** `namedConversationPublicationFiles.ts` (prepare / assert / deterministic copy id
  `uuidv5('file:<tenant>:<source>', operationId)` / receipt-settles-race catch block).
- **New:** `packages/conversations/src/files/publication.ts`:
  - `prepareConversationFilePublication(db, actor, destination {ownerType, ownerId, conversationId?}, operationId, sourceFileIds[])`
    - Computes `request_hash = sha256(actor, destination, operationId, ordered sources)`.
    - Inserts the receipt (`onConflict ignore`).
    - Same hash and already prepared or published ⇒ returns the **original receipt** (idempotent retry).
    - Different hash ⇒ `FILE_OPERATION_CONFLICT`.
    - More than 20 sources ⇒ `FILE_LIMIT_EXCEEDED`.
    - Each source is authorized against its own owner and copied by protected transfer. Each copy is bound to `publication_operation_id`.
  - `publishConversationFilePublication(trx, …)` runs **inside the caller's message transaction**. It locks the receipt, asserts
    every manifest copy is `ready`, not discarded or purged, and matches hash, size and name, then sets `published`.
    Copies are readable only once their receipt is `published`.
  - `abandonConversationFilePublication(db, …)` sets `abandoned` and `discarded_at` on that operation's copies.
- **Does not change:** comment write paths, `persistCommentPublication`, and drafts (L2a supplies the "message" that calls publish).

### 2.6 Digest descriptors + authorized download route adapter

- **New:** `packages/conversations/src/files/descriptors.ts`.
  - `ConversationFileDescriptor {tenant, fileId, fileName, mimeType, size, contentHash}` is the only file shape an email payload carries.
    It carries no path, URL or bytes.
  - `rehydrateConversationFile(db, descriptor, storage, authority)` re-reads the row under **current** owner authority (a
    retained descriptor is not a standing capability, per the reference `assertNamedConversationDeliveryFiles`), derives the
    path, downloads, and verifies length + sha256 ⇒ `FILE_CONTENT_MISMATCH` on drift.
- **New:** `packages/conversations/src/files/download.ts`.
  - `createConversationFileDownloadHandler({ guard, resolveActor, storage })` returns a Next `GET`.
  - Order: `guard` first (the capability route guard, passed in by the mounting card), then session (internal user, no API-key override, per the
    reference route), then owner `canRead`, then published-or-own-pending check, then verified bytes.
  - Any denial is **404**, and storage failure is 503.
  - Response headers: `no-store, private`, `nosniff`, sandbox CSP, `application/octet-stream`, RFC 5987
    `Content-Disposition`.
- **Mismatch flagged:** those headers live in `server/src/lib/co-managed/attachmentResponse.ts:1-8`, which a package cannot
  import. The engine carries its own copy, tagged `// LEVERAGE: pattern conversation-file-engine`. The co-managed file is
  not moved.
- **Unmounted:** no `server/src/app/api/**/route.ts` and no middleware entry (compare `server/src/middleware.ts:281-296`) in
  this card. L1 adds the route file, the middleware session-path entry and `capabilityRouteGuard('ticket-conversations')`.
  So "no route reachable when the capability is closed" holds by construction.
- **Review R2 consequence:** "download route 404s when capability is closed" is demonstrated at handler level (a closed
  guard ⇒ 404 before any SQL) plus "no such path" on the dev server. It cannot be a mounted-route demo until L1.

### 2.7 Cleanup

- **Main seams:**
  - `packages/co-managed/src/uploadCleanup.ts:28` (`cleanupCoManagedUploads`): claim invisibility under `FOR UPDATE SKIP LOCKED`,
    then purge outside the claim, with backoff `least(3600, 2^attempts·60)s`.
  - `packages/jobs/src/lib/handlers/coManagedUploadCleanupHandler.ts:12-19` (`registerUploadCleanupAdapter`).
- **New:** `packages/conversations/src/files/cleanup.ts`, `cleanupConversationFiles(db, tenant, remove, limit≤500)`:
  1. Expire stale `prepared` receipts and pending or unpublished uploads past the retention window (7 days, same as co-managed).
     **Spared:** files any registered retention hook claims (`registerConversationFileRetention(name, (trx, tenant, fileIds) => Set)`,
     which L2a uses for "selected editor files") and every copy whose receipt is `published` ("accepted copies").
  2. Purge discarded rows: storage delete, then `purged_at`, name scrubbed. On failure: attempts++ with backoff.
  3. Mark `cleanup_completed_at` on abandoned receipts with no unpurged copies.
  - Timestamps are bound or `clock_timestamp()` in WHERE only. There is no `now()` in CASE or COALESCE.
- **Mismatch flagged:** the existing upload-cleanup job is `capability: 'co-managed'`
  (`packages/jobs/src/lib/handlers/coManagedUploadCleanupHandler.ts:35,45-47`), so a conversations adapter registered there would
  sweep only co-managed tenants. L0c therefore ships `cleanupConversationFiles` + an adapter factory **unscheduled** (D5). L1 adds a
  `ticket-conversations`-gated maintenance job (`registerMaintenanceJob`, the same shape as
  `server/src/lib/jobs/handlers/coManagedUploadCleanupHandler.ts`).
- **Does not change:** `cleanupCoManagedUploads`, the co-managed job, `MAINTENANCE_FANOUT_SCHEDULES`.

## 4. Test plan

**A. Integration (real migrated DB).** New file `server/src/test/integration/conversationFiles.integration.test.ts`,
two tenants, a synthetic owner type registered in the test, and an in-memory `ConversationFileStorage`:
1. Upload → prepare → publish → authorized read returns identical bytes. The receipt row goes `prepared` → `published` (R1 shows this table).
2. A copy is unreadable while its receipt is `prepared`, and readable after `published`.
3. Abandon → copies discarded → cleanup purges storage objects and completes the receipt.
4. Cleanup spares a retention-hook-claimed file and published copies, and expires an unclaimed stale upload.
5. Cross-tenant read (same `file_id`, other tenant) ⇒ not found.
6. Cross-owner read (actor allowed on owner A, file on owner B) ⇒ not found.
7. Copy without read on the source owner ⇒ rejected.
8. Duplicate `operationId` with the identical request ⇒ the original receipt is returned, with no second copy rows.
9. Reused `operationId` with a different request ⇒ `FILE_OPERATION_CONFLICT`.
10. Size limit: 26 214 401 bytes ⇒ `INVALID_FILE`, and a direct insert violates the CHECK. Count limit: 21 sources ⇒ `FILE_LIMIT_EXCEEDED`.
11. Tampered stored bytes ⇒ `FILE_CONTENT_MISMATCH` on read and on descriptor rehydrate.
12. Purge failure ⇒ attempts and backoff recorded. A retry succeeds.

**B. Unit (package vitest).** Snapshot validation, path derivation and assert, descriptor rehydrate+verify, download
handler (closed guard ⇒ 404 with zero DB calls, unauthorized ⇒ 404, headers), and limit helper parity with the co-managed helper.

**C. Contracts.** Migration lint, tenant manifest `--check` + golden/scope tests, worker-boot (no static worker import), and
hot-path budget tests unchanged.

**Review guide.** Chapter 0 = neutrality: flag-off tenant and co-managed tenant ticket, comment, portal and inbound unchanged;
budgets green. R1 = run suite A, show the `conversation_file_publications` round-trip. R2 = handler 404 with the guard closed, and no
mounted path. Final chapter: kill switch. Because no entry point is gated or mounted in this card, the chapter only shows that
`FORCE_CAPABILITIES=ticket-conversations:off` changes nothing. Without L0a the key is ignored as an unregistered capability.
