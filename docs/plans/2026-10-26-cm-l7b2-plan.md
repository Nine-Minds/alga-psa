# CM L7b2 — Portable restore (design session plan)

Card `df290180-b686-46c1-a16f-b5b96361544a` · wave 6 · hard parent merged: L7b1 · soft: L5.
Reviewer question: "Can an exported workspace be restored into a fresh tenant?"
Authority: `~/cm-redelivery/PLAN.md` §2–3, §5 and `manifests/L7b2.md` win over this plan.

## 1. Intent

L7b1 makes a workspace exportable as a signed, passphrase-protected archive. This card is the other half: take that archive
and reconstitute a working tenant — records, attachment bytes, credential secrets — into an installation that has no prior
co-managed state, and prove the result is a normal tenant whose tickets, files and users open. It is deliberately a
one-way, offline, operator-run path (`server/scripts/restore-portable-workspace.ts`), not a UI and not an activation
workflow: nothing in the product links to it, so a restore can never be triggered from a tenant that is still live.

## 2. What changes

Ordered; each step depends on the one above.

1. **Migrations** (three, re-dated past main's newest; guard with `hasTable`/`IF NOT EXISTS`, no triggers, no backfills):
   - `*_add_portable_restore_suspension.cjs` — the durable marker that a tenant is mid-restore, so background intake and
     workers do not write into a half-populated workspace.
   - `*_retain_portable_workspace_restore_receipts.cjs` — one receipt per restore attempt; the idempotency key.
   - `*_retain_portable_restore_upload_attempts.cjs` — upload/promotion attempts with their outcome, for cleanup and audit.
   All three are new co-managed tables and must be added to the L0 tenant-deletion/export table manifest (gate: manifest
   coverage) and registered as tenant-scoped in `packages/db/src/lib/tenantTableMetadata.ts`.
2. **Records and database restore**: `packages/co-managed/src/portableWorkspaceRestoreFiles.ts` (archive layout, manifest
   verification, per-file classification) and `ee/server/src/lib/co-managed/portableWorkspaceRestoreDatabase.ts` (ordered
   inserts in FK-safe order, tenant rewrite of every row, sequence/identity and citation-safe idempotency). EE-only because
   it drives the EE database helpers.
3. **Bytes and uploads**: `packages/co-managed/src/portableRestoreUploads.ts` (stage → verify hash → promote into the
   storage provider), `ee/server/src/lib/co-managed/portableWorkspaceRestoreUploads.ts` (3-line EE shim that injects the EE
   storage provider). Staging happens before promotion so a failed restore leaves no half-visible file.
4. **Secrets**: `ee/server/src/lib/co-managed/portableWorkspaceRestoreVault.ts` — decrypt the archive's secret section with
   the operator passphrase, re-wrap into this installation's secret store via `@alga-psa/core/secrets`. Never write a
   decrypted secret to a log, temp file or error message; never accept a passphrase from argv (stdin or env only).
5. **Identity and authority**: `packages/co-managed/src/portableRestoreInstallationAuthority.ts` +
   `ee/server/src/lib/co-managed/portableRestoreInstallationAuthority.ts` — refuse if the target installation already holds a
   co-managed relationship, entitlement or restore receipt for that workspace, so a restore cannot overwrite live state.
6. **Operator entry point**: `server/scripts/restore-portable-workspace.ts` (`--inspect` prints the manifest and exclusions;
   `--apply` performs the restore; `--resume` re-runs from the receipt). Matches the surrounding script style in
   `server/scripts/` (`create-tenant.ts`, `rollback-tenant.ts`).
7. **Job and startup wiring, last** (both files are shared hot seams — hunk-level only):
   - `packages/jobs/src/lib/maintenanceJobFanout.ts` (+3) registers the upload cleanup with `registerMaintenanceJob(...)`
     at `scope: 'system'` (`packages/jobs/src/lib/maintenanceJobFanout.ts:191`).
   - `packages/jobs/src/lib/handlers/portableRestoreUploadCleanupHandler.ts` (+17) plus the server registration in
     `server/src/lib/jobs/registerAllHandlers.ts` (+7) via `JobHandlerRegistry`.
   - `server/src/lib/initializeApp.ts` (+4, **main-changed: YES** → 3-way apply, never whole-file restore) starts the
     temporary-file recovery sweep so an interrupted restore cleans up after a restart.
   Where L0b's "jobs registered as data" registry exists, register there instead and keep the handler signature unchanged.

## 3. Boundaries

- **The export side** — archive format, contributor registry, what is included/excluded: L7b1 (hard parent; PLAN §5 "export
  contributor registry" is its seam). This card consumes the format; it must not change it.
- **Activation, billing and the customer-facing "restored workspace" purchase**: L8b (card description: "OUT OF SCOPE …
  Activation billing (L8b)"). No activation wizard exists and none is built here (H §2 L7 excluded list).
- **Per-domain exporters** (time, schedule, meetings, conversations, documents): L7b3.
- **Relationship closure / departure before a restore**: L7a. This card never closes or opens a relationship.
- **`tenants_suspended_reason_check`**: widened by L7a, not here (see R2).
- **Any evidence/ledger machinery**: excluded by PLAN §1 and the card's rules.

## 4. Acceptance

- A1 `npx vitest run server/src/test/unit/product/coManagedPortableWorkspaceRestoreFiles.test.ts` — archive layout,
  classification and rejection of a tampered manifest (320 lines of cases are already specified in the manifest).
- A2 `coManagedPortableWorkspaceRestoreRecords.test.ts` — record rewrite order, tenant stamping, FK integrity.
- A3 `coManagedPortableWorkspaceRestoreVault.test.ts` — wrong passphrase fails closed, no secret material in thrown errors.
- A4 `coManagedPortableRestoreIdentity.test.ts` — restore refused into a non-fresh installation.
- A5 `portableRestoreRecoverySchedule.test.ts` + `portableRestoreUploadCleanupHandler.test.ts` — the sweep and the handler.
- A6 **Round trip**: export with L7b1's exporter in-process, restore into a fresh tenant, then open a restored ticket and a
  restored file. This needs a live installation with storage and the worker; construct the archive in the test rather than
  checking one in (PLAN §1 forbids evidence/fixture media). If the environment cannot host a second tenant, the charter
  must say the round trip was demonstrated only at the record/bytes level — not claim a pass.
- A7 Global gates: migration lint; image boot isolation (server, workflow-worker, email-service and Temporal worker must
  boot with `@alga-psa/co-managed` unresolvable — the `initializeApp` hunk must be inside a guarded import); hot-path
  budget unchanged for psa tenants (the startup hook is one query at most, and none for non-participating tenants);
  tenant-deletion manifest coverage for the three new tables; generated-artifact drift.
- A8 Recorded guide: restore an export into a fresh tenant, open a restored ticket and a restored file; kill switch.

## 5. Risks

- **R1 partial restore**: a crash between record insert and byte promotion leaves a tenant that looks restored. Mitigation:
  the suspension marker plus receipt state machine (`staged → promoted → verified`), and `--resume` keyed on the receipt;
  promotion after verification only.
- **R2 suspension surface**: if the suspension marker reuses `tenants.suspended_at` / `tenants_suspended_reason_check` it
  collides with L7a, which owns that CHECK widening (H §2 L7 deployment). Mitigation: a dedicated co-managed restore flag
  (see open choice), or coordinate the reason value list with L7a before writing the migration.
- **R3 tenancy rewrite**: every row's `tenant` must be rewritten to the target; a missed table silently leaks another
  workspace's data. Mitigation: the file list is driven by L7b1's contributor registry, and A2 asserts that the set of
  written tables equals the set in the archive manifest — not a hand-list.
- **R4 EE/CE parity**: four of the modules are under `ee/server`; the CE build must still boot. Guard the imports and let
  A7's boot-isolation gate prove it.
- **R5 `initializeApp.ts` is main-changed**: whole-file restore would revert main. Take only the recovery-start hunk with
  `git apply --3way` and reconcile.
- **R6 uploads staging size**: temp staging can fill a disk on a large export. Cap the staged bytes, document the cap in the
  charter (H §2 L7 asks for a documented cap) and let the cleanup handler reclaim stale staging.
- **R7 credentials**: an operator passphrase in argv lands in shell history and process lists. stdin/env only, and the CLI
  must refuse `--passphrase=`.

## 6. Open design choices

- **Restore target** (leaning: fresh installation with zero co-managed rows only). Reason: the archive carries ids; any
  existing row set invites merge semantics this card does not own.
- **Where the suspension marker lives** (leaning: a co-managed restore row, not `tenants.suspended_at`). Reason: R2, and a
  tenant suspension has product-wide meaning that a restore should not borrow.
- **Receipt granularity** (leaning: one receipt per (workspace, attempt), resume in place). Reason: idempotency proof for
  the acceptance bar without a new event log.
- **Decided, not open**: no activation UI (H §2 L7 excluded list); no checked-in archive fixtures (PLAN §1); the CLI is
  operator-only and hidden from the product surface registry.
