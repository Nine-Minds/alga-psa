## 1. Intent

One access matrix, evaluated in one place: **customer grant ∩ MSP staff assignment ∩ home RBAC ∩ lifecycle**. An MSP
technician sees a customer ticket only because the customer shared that board, the MSP assigned him, his own role allows the
action, and the relationship is live — and any one of those being withdrawn takes effect on the next read, not on the next
deploy. This card ships the policy engine, the authorized read model every later card calls through, delegated
administration (a real cross-tenant write with immutable receipts), and foreign-actor attribution so a customer-authored
comment renders as a person on the MSP's native ticket screen. The UI is the standing admin need: an **Effective access**
view that answers "why can't QA see this?", plus the delegated-administration panel. No shared ticket screen exists yet (L3).

  ticket pages and queued mail (L3 and L5 re-test this with their own objects); field-redaction configuration UI (none exists)".
- **L1a** owns relationship rows, provisioning, acceptance and `managementPolicy.ts`; this card never writes relationship
  lifecycle and never re-implements the identity/permission primitives.
- **L3b1** owns the handoff state machine, the queue reader and `ticketEditing`; **L3b2** owns the screens; **L3a** owns
  `TicketDetails`/Bento/`CommentItem` seams; **L0c** owns the native write call sites. Here: hunks inside those files only.
- **L0b** owns the tenant-deletion manifest mechanism and the eventBus extension point; this card adds rows, not machinery.
- Field redaction ships **as a mechanism**; no configuration UI, so the guide does not record it. Bulk/deferred items stay out.

  deny, including `escalation_only` making board grants dormant without deleting them. Needs L1a's fixture — a hard parent,

- **A2** Field-redaction unit test: a hidden `status_id` also removes `status.name`; omitted keys, no nulls-as-placeholders.
- **A3** Delegated-grant receipts immutable in app code (update/delete refused by the writer; no trigger dependency).
- **A4** Write admission is the L0 primitive, once: every co-managed write goes through admission (Gate-coverage AST pass + the

- **A5** Attribution: a collaborator comment renders with an author label on the native screen, is not editable by the MSP,
  and never prints "null null"; `CommentItem`/`TicketConversation` keep main's behaviour when no attribution exists.
- **A6** Recorded: H §2 L2 steps 1–9 (share Service Desk, assign MT/MV, three different Effective-access matrices, MX's REST
  probe 404, mode switch, delegated edit, revoke-then-save-fails, MV denied, read-only lifecycle). **Infrastructure this card
  lacks**: no shared ticket screen (L3) — access is shown through the Effective-access view, delegated admin and REST probes,

- **A7** Global gates: migration lint, upgrade-order (N-1), schema-absent neutrality, generated artifacts, tenant-manifest

## 5. Risks

- **R1 shared, main-changed files**: `eventBusSchema.ts`, `comment.ts`, `TicketDetails`, `CommentItem`, `BentoHero`,
  `client-tickets.ts`, `optimizedTicketActions.ts`, `tenantTableMetadata.ts`, `tenant-deletion-activities.ts`. Whole-file
  restore would revert main. Mitigation: hunk-only `git apply --3way`, diff **against main**, manifest line budget per file.
- **R2 actor-name regression** (DO-NOT-PORT #1): the branch's name formatter reverts main's fix; use `userDisplayName`.
- **R3 privilege escalation via delegation**: a delegate must hold the customer's native admin permission *and* a sponsor
  staff assignment. Mitigation: the `coManagedDelegatedAdministrationCases.ts` fixture grants the customer permissions
  explicitly; a test asserts MV (viewer) cannot delegate.
- **R4 permission catalog** (DO-NOT-PORT #27): never insert `co_management:*` into psa roles; the capability-bearing catalog
  entry is filtered by the role editor for unserved tenants. Seed on admission, not by global backfill.
- **R5 `ticket_audit_logs`** `varchar→text` takes ACCESS EXCLUSIVE: run alone with `lock_timeout=2s` + retry, CHECK/FK
  `NOT VALID` with `VALIDATE` in a separate file — or defer the type change (see §6).
- **R6 migration dating**: branch timestamps (`20260906*`) are older than main's `20261023*`; re-date, guard every DDL, run
  `migration-lint`.
- **R7 event replay**: a changed `subscriberId`/processed key can re-run notifications at deploy (#12). Keep main's keys.
- **R8 redaction by inference**: two visible fields must not reconstruct a hidden one; the read model redacts derived
  references and tests the pair.

## 6. Open design choices

- **`ticket_audit_logs` now or at L3 — leaning: columns now, `varchar→text` deferred to L3.** H §2 L2 says "If L3 is the
  first reader of these columns, defer them to L3"; L2's attribution reads `ticket_activity`/comments, not audit logs, so the
  narrow columns suffice and the lock-taking type change lands where the first wide reader appears. Final call at the session.
- **Dormant grants under `escalation_only` — leaning: retain, gate on `visibilityMode`.** Switching modes must not silently
  discard the customer's configuration; every reader already gates on the mode (reference `policy.ts:readCustomerScope`).
- **Redaction storage — leaning: a `redacted_fields text[]` column on the policy row**, not a new table: one relationship has
  one policy, and it keeps the migration count down. Open because a config UI may later want per-resource rows.
- **Decided by authority, not open**: no field-redaction UI (H §2 L2 Excluded); `co_management:*` never granted to psa roles
  (DO-NOT-PORT #27); the whole card is behind the capability gate, never raw `release-v2-0-feature` (PLAN §2).
- **Delegated-admin surface — decided**: board display settings and user profile only (H §2 L2 step 5 and
  `delegatedAdministration.ts`), not credentials, billing or roles.
