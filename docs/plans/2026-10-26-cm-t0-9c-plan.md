## 6. Acceptance bar

Automated, must be green at HEAD. Each test is named with the item it proves.

**A1 — same-task ordering (C9).** `TaskCommentThread.loadSequence.test.tsx`: mount with `getTaskComments` returning a deferred promise D1; post a reply through the mocked editor (the path the existing suite already drives) so `handleCommentAdded` issues D2; resolve D2 with `[root, reply]`; then resolve D1 with `[root]`. Assert the reply is still rendered and the thread still shows "1 reply". **Red on main**: D1 lands last and erases the reply.
Deterministic: two hand-controlled deferreds resolved inside `await act(...)`; no timers, no `waitFor` polling, no sleeps.

**A2 — cross-task ordering (C9).** Re-render with `taskId="task-b"` while task A's request is in flight; resolve B, then A. Assert A's comments and A's error state never enter the DOM, and `onCommentCountChange` is never called with `('task-a', …)` after B won. The in-component reset on `taskId` runs in an effect, so on its own it would let the commit that switches task paint A's thread for one frame. The render site (`TaskForm.tsx`) therefore keys the thread by `task.task_id`, so a task switch mounts a fresh thread with empty state. The effect reset is kept as the guarantee for any consumer that does not key the thread. **Red on main**: A's response writes into B's thread and reports A's count (the list badge shows the wrong task's count).

**A3 — superseded failure does not poison the thread (C9).** The superseded request resolves with `{ actionError: … }` after the current one succeeded. Assert no `role="alert"`, no toast-driven error state, comments intact. **Red on main**: the error branch returns early and leaves whatever arrived first.

**A4 — load-error state (C9).** The current request returns an action error. Assert `comments.loadError` text is rendered with `role="alert"`, and that the "Add Comment" button, the page create shortcut's action and the "No comments yet" empty state are all absent. Reason: the thread's contents are unknown, so offering a composer invites a post into a thread the user may not be able to read, and showing "be the first to comment" states something false.
The full error state applies only to a thread that has never loaded (`threadUnknown`). A failed *refresh* of a loaded thread keeps the last good list on screen, with a banner and Retry above it (test: "a failed refresh keeps the loaded list visible…"). The error state is recoverable, not terminal: it offers a Retry (`comments.retry`) that re-runs the load on its own, without depending on the comments that failed to load, and a successful load clears the error (test: "retry re-runs the load…"). Draft safety is asserted on content, not on mount: the editor stand-in holds its text in component state, and the test types a draft, fails a refresh triggered from elsewhere in the thread, and checks the text is still there. The load error gates *opening* a composer; it never unmounts one already open. A composer stays mounted, with its draft, across a failed refresh and is closed only after a successful load or an explicit cancel (test: "a failed refresh keeps the open composer mounted…"). The page-create shortcut is asserted disabled in the error state. The reaction batch carries the same supersession guard, and a test resolves an older batch after a newer one and asserts the older one is dropped.

**A5 — checklist delete runs inside the transaction boundary (C10a).** `ticketChecklistActions.delete.test.ts` with `@alga-psa/db` mocked: `createTenantKnex` returns a base connection that the test fails on if it is queried at all; `withTransaction` runs the callback against a recording trx and records commit/rollback. Assert (i) the guard read and the delete both issue on the trx and the base connection is never touched, (ii) a zero-row delete returns the "Checklist item not found" error, (ii′) the guard read is tenant-scoped: the fake honours the effective predicate, the test asserts the read's `where` includes the tenant, and an item belonging to another tenant is not found and not deleted, (iii) when the delete throws, the recorded outcome is a rollback and the error is not swallowed. **Red on main**: the delete hits the base connection — assertion (i) fails on the first statement.

**A6 — the label names its input (C10b).** `Input.labelAssociation.test.tsx`: `getByLabelText('Name')` resolves to the input both when the caller passes `id` and when it does not, and the associated id is stable across a re-render. **Red on main**: Testing Library finds "a label with the text but no form control".

**A7 — regression, existing suites.** `packages/projects` (`TaskCommentThread.threadedReplies.test.tsx`), `packages/tickets` checklist unit suite and `server/src/test/integration/ticketChecklists.integration.test.ts:253`, `packages/ui` component suite, and `npm run test:i18n` all stay green.

## Risks

1. **Locale parity.** A new key in nine locale files must land with regenerated pseudo-locales or `test:i18n` fails the PR. Mitigation: generate, never hand-edit; the only human-authored change is the real translations.
2. **`Input` ids appear where there were none.** Inputs rendered without `id` gain a `useId`-based id. Nothing selects `Input` by DOM id in the repo today (the `getElementById` call sites target ids their callers pass explicitly) and there are no Input snapshots, but a suite that queries by `id` on an id-less `Input` would now see an unexpected-but-valid attribute. A7 covers it.
3. **Thread-scoped reset timing.** Resetting on `taskId` change instead of on every load deliberately keeps the previous list visible after a post-refresh, and a failed refresh keeps it visible behind a banner rather than replacing it with the error state. That is a behaviour choice (no flicker, keeps reaction state). If a reviewer wants the reference's blank-then-fill, it is a one-line move into `loadComments`; the plan records why it is not there.
4. **Hunk collision with L4c on `TaskCommentThread.tsx`.** Both cards edit the same file. Mitigated by keeping this card's hunks in the loader/state region and refusing the presentation hunks; L4c's rebase should then be additive.
5. **The delete's guard changes behaviour slightly.** A delete for an item that does not exist now fails at the `forUpdate` read rather than at a zero rowcount. Same user-visible error, same message; a concurrent double-delete loser now sees a clean rollback instead of a post-commit "not found".
6. **A5 proves the boundary, not a DB-level rollback of a multi-statement unit.** The delete is currently the only write in the unit of work, so there is no second statement whose failure a DB test could observe. A5 asserts single-connection use and rollback wiring; when L0c adds admission (a read) and any companion write joins, atomicity follows from the boundary rather than from a new test. Stated so the bar is not overclaimed.
