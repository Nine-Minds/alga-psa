## T16 — Revocation race

**Implemented.** [sharedWork.ts](../../packages/co-managed/src/sharedWork.ts) retains current relationship, staff membership, resource grants, home authorization, and credential locks through the operation. It admits verified sessions, API keys, and a separate read-only notification recipient principal. [policy.ts](../../packages/co-managed/src/policy.ts) and [ticketHandoffs.ts](../../packages/co-managed/src/ticketHandoffs.ts) serialize reductions and retain authorized history before removing access. [relationshipClosure.ts](../../packages/co-managed/src/relationshipClosure.ts) seals history and terminates trust in the same transaction. Ticket/task conversation, attachment, queue, notification, and workflow adapters use current source admission rather than treating cached projections or queued bodies as authority.

**Existing validation.** `server/src/test/integration/coManagedBootstrap.integration.test.ts` includes actual PostgreSQL cases named “rechecks revoked queue scope and session expiry after waiting for lifecycle locks”, “suppresses queued channels on revoked access”, “revalidates attachment read scope, deleted parents and live grants before reaching storage”, and “project search uses current sources and suppresses stale or deleted task-comment bodies without waiting for indexing”. It also covers stale command receipts, removed staff assignments, task grants, notification recipients, and final credential expiry. `workflowTicketAuthority.ts` derives its principal from retained workflow execution/definition/version rows, not a request-selected foreign tenant.

**Remaining required evidence.** Exercise the assembled open-page/search/download/queued-delivery journey while revoking access in another session. The source audit found no distinct missing revocation primitive requiring another implementation. Previously delivered content cannot be made unknown to its reader; the requirement is to deny subsequent protected reads/writes/deliveries, not to promise erasure from a browser's memory.

## T17 — Lapse and recovery

**Implemented.** [co-managed-entitlements.ts](../../packages/licensing/src/lib/co-managed-entitlements.ts) maintains a durable lapse start and 30-day deadline, blocks growth immediately, preserves the earlier lapse through inadequate renewal, and treats reduced capacity as a deficit without deleting users. [co-managed-lifecycle.ts](../../packages/licensing/src/lib/co-managed-lifecycle.ts) retains entitlement/relationship admission through operational transactions, distinguishes pending acceptance, terminated, grace, and read-only states, and leaves non-co-managed PSA operation independent. Export, reading, acceptance, license recovery, and upgrade have narrow separate admissions. Interactive and background writers have extensive adapters; deferred email/artifact processing retains identities and retries after renewal.

**Existing validation.** The PostgreSQL suite includes “blocks growth immediately on lapse, including consuming an already-issued invitation”, “renews the original relationship without repeating activation or provisioning”, “refunds the claim when grace expires during source fetch and resumes the same inbox exactly once after renewal”, and “rolls back documents when expiry wins during upload, refunds the attempt, and resumes exactly once after renewal”. It also exercises actual project, KB, asset, schedule, interaction, timer, timesheet, API, comment, import, and workflow write boundaries during lapse.

**Remaining required evidence.** Confirm the composed hosted and self-hosted lapse/renewal journey in the deployed dev worker wiring. No additional lapse behavior was shown missing by this bounded audit. Avoid treating every historical checkpoint mentioning a possible writer as a demonstrated bypass; require a concrete reachable unguarded write before adding implementation work.

## T18 — Archive, portable export, and restore

**Implemented.** [archiveFinalization.ts](../../packages/co-managed/src/archiveFinalization.ts) discovers participated-in ticket/task work from actual contributions, assignments, handoffs, and time. It composes shared conversation history, MSP-private history, work metadata, and retained time evidence. [archiveFiles.ts](../../packages/co-managed/src/archiveFiles.ts) copies published ticket/task conversation bytes into MSP ownership while authorized; [archiveReads.ts](../../packages/co-managed/src/archiveReads.ts) reads retained evidence without reopening customer data. Sealed manifests survive later object upload completion and customer-source deletion.

[portableWorkspaceExport.ts](../../ee/server/src/lib/co-managed/portableWorkspaceExport.ts), the flagged customer export page, and `/api/co-management/export` produce one encrypted, authenticated package with explicit record graphs, native/document/conversation/meeting files, and separately re-encrypted business credentials. [portableWorkspaceRestore.ts](../../ee/server/src/lib/co-managed/portableWorkspaceRestore.ts), the native database/file/vault adapters, and `server/scripts/restore-portable-workspace.ts` restore new identities into a suspended tenant. Sessions, provider OAuth state, signing keys, and live sponsorship are excluded. Imported users remain inactive until explicit paid activation. Posted task conversation attachments now participate in export, strict manifest validation, and native task-document restoration.

**Existing validation.** The main PostgreSQL suite covers source deletion, scope reduction, private-history exclusion, archive sealing rollback, byte retention, and qualified historical attribution. `helpers/coManagedPortableWorkspaceExportCases.ts` tests actual encrypted export, a native PostgreSQL restore with usable vault/files, operator CLI inspection, idempotent restore receipts, failed/late upload recovery, and hosted/self-hosted activation. Unit suites cover manifest closure, identity remapping, rich text, authenticated framing, provider receipts, bounded temporary storage, and transfer cancellation. These are substantially more than a JSON export helper.

**Follow-up implemented and verified.** portable workflow exports now include task business snapshots and curated activity, including `workflow_tasks.response_data` and completion `formData`. Native restore records these in `audit_logs` with remapped task identity and source-qualified attribution; it creates no executable task/claim/event rows. Current workflow read policy and field redaction are enforced. Earlier packages without the two new tables remain supported. Focused PostgreSQL export/isolation/redaction cases and the authenticated native database restore journey verify response retention, inactive historical authors, excluded provider context, and absence of restored task execution. Destination access uses existing audit permissions.

**Native-library boundary clarified.** Native KB/document/vault actions and document view/download routes resolve the authenticated home tenant and its document authority; public tenant logos are an explicit publication exception. Shared work does not automatically grant foreign native document-association or vault access. The supported shared-file archive captures published, qualified conversation attachments. Native libraries remain covered by the customer portable export. This review did not establish a missing MSP archive exporter for automatically shared native-library files, because no such automatic foreign grant exists.

**Final archive follow-up — `febea98256`.** Task file URLs and the download route now preserve the qualified task parent. Archive work and history pagination apply current admission before visible page/count decisions. Six focused PostgreSQL cases and nine archive UI cases passed; this closes the concrete final-review archive defects.

Validate a restored workspace through native screens and downloads after activation, with the source unavailable. That journey should verify required configuration and authored references rather than adding generic configuration tables wholesale.

**Not additional release scope by itself.** Automatic hosting migration is explicitly excluded. A new hosted restore checkout is not necessary to satisfy the licensed isolated self-host restore path; hosted activation currently accepts an already provisioned paid native subscription. Live S3 deployment verification is operational validation, not a requirement to build a new storage provider or multipart engine. Avatars/logos stored as native documents with `document_associations.is_entity_logo` already fall within the document projection; do not assume a separate avatar exporter is missing solely because core user rows have no avatar field. Unknown external URLs must not be fetched or rewritten speculatively.

## T19 — Independent upgrade

**Implemented.** [independentUpgrade.ts](../../packages/co-managed/src/independentUpgrade.ts) retains the customer administrator, entitlement, revision, and operation identity; initializes paid capabilities and closes sponsorship atomically; and records one durable receipt. The production activity `product_upgrade_co_managed` uses the shared independent PSA initialization in `ee/temporal-workflows/src/db/product-upgrade-operations.ts`. Hosted checkout/reconciliation uses the customer's own Stripe customer/subscription and separate purchase recovery; self-hosted upgrade uses tenant-bound signed licenses. Allocation release belongs to the closure receipt. Historical operational time remains non-invoiceable after conversion.

**Existing validation.** The main PostgreSQL suite exercises both entitlement adapters, seat sufficiency, source data retention, one closure/allocation release, post-departure conversion, seed rollback, final session expiry, customer-owned checkout/payment recovery, paid seat changes, and independent tenant license renewal. `coManagedUpgradeWorkflow.test.ts` confirms a single atomic co-managed activity rather than the AlgaDesk subscription-swap sequence. `coManagedUpgrade.test.tsx` covers confirmation, lost acknowledgement retries, payment recovery, and session refresh after conversion.

**Remaining required evidence.** Actual configured Stripe test-mode purchase/webhook/worker execution and the equivalent self-host operator journey remain launch validation. No new independent-upgrade backend behavior was demonstrated missing here. Configuring the hosted co-managed price and deploying the external signed-capacity issuer remain the explicit plan dependencies, not proof that the implemented upgrade substitutes the MSP subscription.

Existing byte-retention cases cover archive files; billing cases cover qualified sources, private fields, operational-time invoice rejection, edits and approvals. The bootstrap fixture applies the feature migrations to a schema-only clone; several migration replay/check/immutability cases are exercised. Complete the browser invoice/PDF and archive-download smoke against deployed storage; the actual deletion, surviving authorized archive read, and native invoice HTML rendering are now established by the focused journey above.
