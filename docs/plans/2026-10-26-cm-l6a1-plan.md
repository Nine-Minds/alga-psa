# L6a1 — Native time seam (time-source providers)

Reviewer question: *Do all native time reads and writes go through one time-source seam that a participating workspace can supply a provider to, with zero visible or query cost change for a PSA tenant?*

Base: `origin/main` @ `058d45c388` · Reference: `feature/co-managed-it` @ `2d00cb6f0e` (merge-base `7e8d87a948`) · Worktree: `feature/cm-l6a1-native-time-seam-time-source-providers` · Card `61bf6c38`, wave 3, hard parents L1a + L3a + T0-3.

## Intent

Time is the one part of the product where a shared ticket produces money on one side and a cost record on the other. Today every time action, REST controller and period job reaches straight into `time_entries`, `time_sheets` and `time_periods` with its own SQL; the reference branch makes each of those call sites branch on `@alga-psa/co-managed`. This card replaces that with a seam: native time remains exactly what it is (same actions, same numbers, same query count), but every read and write is expressed against a `TimeSource` interface whose default implementation is today's behaviour. L6a2 (native co-managed time provider, billing modes, work refs, effort split) and L6c (scheduling) register implementations later; this card only builds the socket and proves the native path is untouched.

## What changes

**1. The contract — `packages/scheduling/src/lib/timeSource/timeSource.ts` (new, types only).**
Zero runtime imports (every action/service import is `import type`, so importing the seam never loads a server module). Method names deliberately match the native function they replace, methods are plain functions (no `this`), and each returns an explicit miss:

```ts
export interface TimeSourceMiss { handled: false; reason?: 'not-served' | 'native-work' }
export type TimeSourceResult<T> = TimeSourceMiss | ({ handled: true } & T);
export interface TimeSource {
  readonly kind: TimeSourceKind;                 // 'native' | (string & {})
  sheets:   { read; list; open; command; comment };          // time_sheets
  periods:  { read; readSettings; command; commandSettings }; // time_periods + settings
  entries:  { read; list; admit; lockBillingMode; review; remove };
  timer:    { start; stop; cancel; active };                  // time_tracking_sessions
  work:     { resolveItem(ticketId); billingContext(item) };  // work-item lookup
  retain:   { participation(entryId) };                       // L2 retainer registry call
}
```
`handled:false` is the contract that makes the native path free: a provider may only answer after the discriminator, and the discriminator may not query (see rule 3).

**2. The native implementation — `timeSource/nativeTimeSource.ts` (new).** A frozen module singleton (`kind:'native'`), every method a lazy forwarder (`const lazy = (load, key) => (...args) => load().then(m => m[key](...args))`) into the modules the call sites use today, returning `{ handled:true, ...result }`. Byte-identical arguments and results; errors are not caught, wrapped or retried, so existing error mapping (`timeSheetActionErrors.ts`) keeps working. Module-level singleton means no provider import and no registration order dependency for `psa`.

**3. Selection — `timeSource/index.ts` (new).** `registerTimeSource(kind, factory)` (idempotent per kind, throws on a second registration), `resolveTimeSource(tenant)` returning native when nothing is registered. The discriminator is **data already in hand**, never a new query: explicit row/work-item markers (`work_item_type === 'co_managed'`, `work_item_type === 'interaction'`, a `co_managed_*` id) or L0a's cached serving verdict (`serves(tenant)`, PLAN §2). PSA tenants therefore pay 0 statements and the schema-absent gate holds: with none of this card's migrations applied, native path executes the same SQL as main.

**4. Wire the call sites in this order** (each step keeps the native branch verbatim):
1. `packages/scheduling/src/lib/timeEntryWriteCore.ts` — `persistTimeEntry`, `deleteTimeEntryCore`, `getWorkItemBillingContext` call `entries.admit`/`entries.lockBillingMode`/`work.billingContext` first; on `handled:false` run today's body untouched. Base already threads `contractLine`/`WorkItemBillingContext` through here (verified in base, L65-160), so the seam adds a parameter, not a rewrite.
2. `actions/timeEntryCrudActions.ts`, `timeEntryActions.ts`, `timeEntryWorkItemActions.ts`, `timeEntryChangeRequestActions.ts`, `timeEntryHelpers.ts` — save/get/review/delete/change-request entry points.
3. `lib/stopwatch/stopwatchCore.ts` + `actions/stopwatchActions.ts` + `lib/stopwatch/stopwatchTypes.ts` — `timer.*` around main's existing session table; native session behaviour unchanged (`startSession`/`logSession`/`discardSession` verified in base).
4. `actions/timePeriodsActions.ts`, `models/timePeriod*.ts`, `lib/timePeriodMaterialization.ts`, `lib/timePeriodSuggester.ts`, `lib/timePeriodAutomation.ts` — `periods.read`/`periods.command`; the nightly path in `server/src/lib/jobs/tenantPeriodMaintenance.ts` resolves the source once per tenant, not per period.

## Boundaries

- **L6a2 owns** the provider itself: billing-mode semantics, work references, operational fields, effort split, co-managed admission. This card ships a seam with no co-managed provider registered — by design, so nothing here can advertise a capability that does not exist.
- **L6c owns** schedules, appointments, interactions and Teams meetings on shared work (`commandCoManagedNativeSchedule` and friends stay out).
- **T0-3 owns** `timePeriodCadence.ts`, `createNextTimePeriod` removal and the REST time-sheet `created_at`/`updated_at` fix (PLAN §5 T0 row; T0-3 is a hard parent). L6a1 must not re-fix them.
- **T0-1 then T0-2 own `billingEngine`.** L6a1 touches no invoice generation and no `lateHourlyTime` path.
- **L3a owns** `TicketDetails`, `Bento` and `CommentItem` (PLAN §5 hot seams); this card's only ticket hunks are the `timeSummarySlot` and work-item resolution lines its manifest names.
- **L2 owns** the access-reduction retainer registry; L6a1 calls `retain.participation` and registers nothing into L2's engine.
- **Do not port**: `timeEntryContract.ts`/`timeContractCandidates.ts` eligibility broadening and the explicit-line rejection (DO-NOT-PORT #16); `getTimeEntryBillingMode` requiring `time_entry:read` (#16); tenant-wide `billing_mode='operational'` probes anywhere (#17); `resolveTimeEntryContract`'s `FOR SHARE` on `tenants`.

## Acceptance

- **A1 Seam completeness.** A static test (`packages/scheduling/src/test/timeSourceCoverage.static.test.ts`) enumerates the module list above and fails if any file imports `@alga-psa/co-managed` or calls `time_entries`/`time_sheets`/`time_periods` outside `nativeTimeSource.ts` and the collection helpers. This is the card's real bar.
- **A2 Native equivalence.** `schedulingTenantScoped.contract.test.ts`, `timeEntryChangeRequestActions.test.ts`, `timeEntryCrud.changeRequests.test.ts`, `timePeriods.test.ts` and the billing golden suites pass unchanged. Amounts are not re-baselined.
- **A3 0-query neutrality.** Hot-path budget entry for "time entry create/approve" shows the same statement and lock counts as main, and no denylisted table name appears.
- **A4 Schema-absent.** Flag-off suite (plus Emerald) against main's schema: time entry save, submit, approve, generate period, stopwatch start/stop/log all behave as main.
- **A5 Migration lint + upgrade order** green; `VALIDATE` durations recorded from a staging Citus snapshot.
- **A6 Provider double.** One focused test registers a fake provider returning `handled:true` for one ticket-scoped entry read and asserts the native SQL is skipped — this is how the socket is demonstrated **without** L6a2. The guide for this card is therefore *not* H §2 L6 steps 4–8; those belong to L6a2. Say so in the guide rather than faking it.

## Risks

- **Seam becomes a query.** Any `resolveTimeSource` that reads `tenants` per call breaks the budget. Mitigation: selection takes the work item/row marker or a value already fetched; A3 fails the PR if a statement appears.
- **Two dispatch styles.** REST services and server actions would naturally grow different `handled` conventions. Mitigation: the `TimeSourceResult` type is the only result shape; A1 forbids a local `if (coManaged)`.
- **Migrations vs N-1.** Adding `billing_mode NOT NULL` to `time_entries` is safe, but backfilling rows or making it required for old writers is not. Mitigation: no backfill; nullable additions on the timer table; separate `VALIDATE` file.
- **Bundle leak.** Importing the seam from a client component could drag server code into the browser. Mitigation: types-only contract, lazy forwarders, and a build check that the client bundle does not contain `timeEntryWriteCore`.
- **Reference timer trigger.** `preserve_native_time_tracking_session()` enforces identity immutability with `FOR SHARE` on `tenants` per row and is Citus-skipped. Mitigation: not shipped; L6a2 enforces the same invariant in the write core and tests it.
- **`time_sheets.notes` reader ordering.** The column ships in this image, but any read of it must tolerate its absence (H §3 rule 8). Mitigation: selection lists `notes` only inside the provider path.

## Open design choices

- **Registry vs injection (open, leaning registry).** A module-level `Map` matches L0b's "registries as data" pattern and avoids threading a source through 40 call sites; the alternative is an explicit composition object passed from `server/src/lib/initializeApp.ts`. Leaning: registry, with a dev-time assertion that a second registration for a kind throws, because L6c and L6a2 both register.
- **Where `timer.*` dispatch lives (open, leaning callers).** Putting it inside `stopwatchCore` would hide it from the REST stopwatch service; leaning is the two call sites (`stopwatchActions`, `ApiTimeEntryService` stopwatch endpoints) resolve first so both surfaces are visibly gated.
- **`interaction` work items (open).** Base's `getWorkItemBillingContext` already resolves `interaction` client ids, so the seam can host them now; leaning yes, types only, no behaviour change, because L6c needs the slot.
- **Forced by authority, not open:** no second timer table (H §2 L6 "Excluded … reconcile with main's `time_tracking_sessions`"); no triggers on `time_entries`/`invoice_time_entries` (#17); the "operational time is never invoiced" invariant is app code (H §2 L6 acceptance); `cancel-tracking` carries `time_entry` RBAC (#25); `timePeriodCadence.ts` belongs to T0-3 (DAG-REPORT R10).
