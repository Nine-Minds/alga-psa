## The contract (exact)

`packages/tickets/src/lib/ticketDataSource.ts` — types and pure helpers only; **zero runtime imports** (every action import is `import type`, which erases, so importing the seam never loads an action module or its server dependencies).

```ts
export type TicketDataSourceKind = 'native' | (string & {});

export interface TicketCapabilities {           // exactly these 26 booleans
  bundles; delete; tags; credentials; externalLinks; checklist; documents; assets;
  materials; billing; quickInvoice; emailLogs; activityLog; reactions; live; survey;
  appointmentRequests; navigation; scheduling; timeEntry; sla; duplicate;
  createTemplate; createWorkflow; createProjectTask; categoryCreate;   // all: boolean
}
export type TicketCapabilityKey = keyof TicketCapabilities;
export const NATIVE_TICKET_CAPABILITIES: Readonly<TicketCapabilities>;   // all true, frozen
export const NO_TICKET_CAPABILITIES: Readonly<TicketCapabilities>;       // all false, frozen
export const TICKET_WRITE_ACTION_CAPABILITIES: readonly TicketCapabilityKey[];
  // ['delete','duplicate','createTemplate','createWorkflow','createProjectTask','quickInvoice','categoryCreate']

export type TicketRefreshMode = 'soft' | 'reload';
export interface TicketScreenBehavior {
  refresh?: (mode: TicketRefreshMode) => void | Promise<void>;  // absent = today's behaviour
  backHref?: string;                                            // absent = '/msp/tickets'
  readOnly?: boolean;                                           // absent = writable
  frozenFields?: readonly string[];                             // per-field, writer may exist
}
export const TICKET_SCREEN_FIELDS: readonly string[];  // 18 keys: title, description, status_id,
  // priority_id, category_id, subcategory_id, board_id, assigned_to, due_date, response_state,
  // client_id, contact_name_id, location_id, billing_profile_id, itil_impact, itil_urgency,
  // additional_agents, watch_list
export function resolveTicketFrozenFields(
  screen: Pick<TicketScreenBehavior,'readOnly'|'frozenFields'>, extra?: readonly string[],
): string[];   // dedup, screen fields first, then `extra` (live conflicts)

export interface TicketEditorRestrictions { disallowImages?; disallowFiles?; disallowMentions? }
export interface TicketConversationConfig { editor?: TicketEditorRestrictions }   // L4a extends

export type TicketScreenLayout = 'entry' | 'grid';
export interface TicketSlotArgs { ticket: ITicket; layout: TicketScreenLayout; refresh: () => void }
export interface TicketTimeSlotArgs extends TicketSlotArgs { timeEntriesRefreshKey: number }
export interface TicketScreenSlots {
  appSection?: (a: TicketSlotArgs) => React.ReactNode;      // Entry properties column + Grid tile
  timeSummary?: (a: TicketTimeSlotArgs) => React.ReactNode; // beside the time summary
}
export interface TicketTimeWorkItem { workItemType: WorkItemType; workItemId: string }
export interface TicketTimeConfig {
  resolveWorkItem?: (t: Pick<ITicket,'ticket_id'>) => TicketTimeWorkItem;   // default: the ticket
  fetchTimeEntries?: (ticketId: string) => Promise<TicketTimeEntriesSummary>; // default: scheduling cb
}

export interface TicketDataSource {
  readonly kind: TicketDataSourceKind;
  readonly boundTicketId?: string;      // documentation only; see Risks R8
  readonly capabilities: TicketCapabilities;
  readonly screen: TicketScreenBehavior;
  readonly conversation: TicketConversationConfig;
  readonly slots: TicketScreenSlots;
  readonly time: TicketTimeConfig;
  readonly ticket; comments; people; resources; options; closeRules; bundles; checklist;
  readonly externalLinks; activity; email; materials; tiles; tags; avatars; viewer;
}
export type TicketDataSourceOverrides; // one level of Partial per group
export function composeTicketDataSource(base, overrides): TicketDataSource;
export function resolveTicketTimeWorkItem(ds, ticket): TicketTimeWorkItem;
```

**What the native implementation returns.** `nativeTicketDataSource` (`lib/nativeTicketDataSource.ts`) is a frozen module-level singleton: `kind: 'native'`, `capabilities: NATIVE_TICKET_CAPABILITIES`, `screen/conversation/slots/time: Object.freeze({})`, no `boundTicketId`, and every method a lazy forwarder

```ts
const lazy = (load, key) => (async (...args) => (await load())[key](...args));
```

so a call is **byte-identical in arguments and return value** to today's direct call — the same action result object (including returned `ActionMessageError`/`ActionPermissionError` values; the seam never unwraps, retries or rethrows), and the export is read at call time so `vi.mock`/`spyOn` on an action module still intercepts. Two invariants: the forwarder's module specifier must be the one main's component used (`getTicketChecklistItems` → `checklists/ticketChecklistActions`, because `TicketDetails.tsx:70` used that, while `TicketChecklistSection.tsx:48` used the barrel), and importing the seam must perform no call and no eager import.

**Where the seam is injected.** `components/ticket/TicketDataSourceContext.tsx` (`'use client'`): a React context whose **default value is the native singleton**, plus `TicketDataSourceProvider`, `useTicketDataSource`, `useTicketScreenReadOnly`, `useTicketCapabilities`, `useTicketCapability`, `runTicketRefresh(ds, mode, router?)`, `useTicketReload()`. The native route mounts **no provider at all** — `server/src/app/msp/tickets/[id]/page.tsx` → `MspTicketDetailsContainerClient` → `TicketDetailsContainer` → `TicketDetails` reads the default. A foreign screen (L2's `SharedTicketScreen`) mounts the provider above the same `MspTicketDetailsContainerClient`; the components are identical in both worlds, and no component may branch on `kind` (pinned by contract test A11). The RSC bootstrap (`lib/ticketScreenBootstrap.ts`) is **not** part of this seam: server components keep calling actions; a foreign screen builds its own `ticketData`-shaped payload.

Completeness rule for this card: the seam covers every *ticket-scoped action*. It deliberately does not cover the cross-feature contexts the screen already consumes (`useDocumentsCrossFeature`, `useSchedulingCallbacks`, `useTags`, `useQuickAddClient`, `useStopwatch`) — the rule for those is "`capabilities.X === false` ⇒ that surface is never mounted, so its provider is never asked".

### 4.1 Capability affordances (section / drawer / button)

Rule: **`capabilities.X === false` ⇒ the surface is absent — no disabled shell, no placeholder, no "not available" copy.** `readOnly` is a separate axis: it is the *viewer's* write permission, so it freezes fields and hides write affordances while keeping every read section.

| Level | Capability | Where the absence happens |
|---|---|---|
| section | `checklist`, `documents`, `credentials`, `externalLinks`, `materials`, `billing`, `sla`, `timeEntry`, `scheduling`, `appointmentRequests`, `assets`, `survey`, `tags`, `navigation` | Entry: `{capabilities.x ? (… ) : null}` around the section (`TicketDetails`); Grid: same gate around the tile (`TicketBentoLayout`), plus `effectiveHideX = hideX \|\| !capabilities.x` for the props that only know `hide*` |
| drawer / dialog | `delete` (delete dialog), `bundles` (propagation dialog), `emailLogs` (email log drawer), `activityLog` (activity drawer + its opener), `duplicate`/`createTemplate`/`createWorkflow` (menu items), `live` (presence + connection banner) | not mounted at all — a closed drawer never exists |
| button / inline action | `delete`, `duplicate`, `createTemplate`, `createWorkflow`, `createProjectTask`, `quickInvoice`, `categoryCreate` | header actions and injected slots; `composeTicketDataSource` also *derives* all `TICKET_WRITE_ACTION_CAPABILITIES` off when `screen.readOnly` is true, so a source cannot accidentally offer Delete on a read-only screen |
| field | `screen.readOnly` ⇒ all 18 `TICKET_SCREEN_FIELDS`; `screen.frozenFields` ⇒ just those; union with live-conflict keys | one list: `resolveTicketFrozenFields(screen, Object.keys(liveFieldConflicts))` → `liveFrozenFields` on `TicketInfo`/`TicketProperties`/`TicketBentoLayout`/`BentoHero`; drives `isFieldFrozen`/`isFrozen`, and hides the team tile / watch list / additional-agents card outright |
| composer | `screen.readOnly` | `TicketConversation readOnly` prop: no add-comment button, no composer, no sticky dock, no reply, no edit/delete, no page-create shortcut; documents/materials/credentials/links render their read-only variant |

`readOnly` does **not** imply a smaller `frozenFields` list and `frozenFields` does **not** imply read-only: a writer on a shared ticket gets `frozenFields: ['board_id']` with an editable everything-else.
