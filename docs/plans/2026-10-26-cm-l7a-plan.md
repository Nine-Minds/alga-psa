# CM L7a — Departure, closure & licence lapse (design session plan)

Card `9b4d4ab7-9c36-494d-9e7c-cb78888d695c` · wave 6 · hard parents merged: L4b, L1b, L0c · soft: L3b2, L5, L6a2.
Reviewer question: "What happens when a relationship ends or a licence lapses: does each side keep exactly what it should,
read-only where required?"
Authority: `~/cm-redelivery/PLAN.md` §2–3, §5 and `manifests/L7a.md` win over this plan.

## 1. Intent

Every other L-card assumes the relationship is healthy. This one is the ending: the MSP ends co-management, and trust must
close on *every* path at once while the customer keeps every ticket, user and file it already owned; the MSP keeps an
archive of the shared work it did, and nothing private. Separately, when an entitlement lapses, the relationship must go
read-only — not dark — so both sides can still read and export, and a renewal restores writes with deferred intake
processed exactly once. Delivery is one idempotent closure operation, one participation-evidence-only archive, and one
lifecycle state the L0c choke point enforces.

## 2. What changes

Ordered: state, then closure, then reads, then enforcement, then the long-tail deadline.

1. **Migrations** (two new tables; expand-only, re-dated past main's newest, tenant-distributed with `tenant` in every
   unique index): `create_co_managed_relationship_closures` (unique `(tenant, relationship_id)` — this constraint *is* the
   "released exactly once" guarantee) and `create_co_managed_archive_manifests`. Both go into the L0 tenant-deletion/export
   manifest and `packages/db/src/lib/tenantTableMetadata.ts` (+4 lines, hot shared file: hunk-level only).
2. **Closure as an idempotent state machine**: `packages/co-managed/src/relationshipClosure.ts` — close trust, write the
   closure row, release the seat allocation exactly once, snapshot the archive manifest. `departure.ts` holds the
   pre-flight review model the operator sees before confirming. Actions:
   `server/src/lib/actions/coManagedDepartureActions.ts`; UI `CoManagedDeparture.tsx` mounted in
   `server/src/app/msp/co-management/departure/page.tsx` through L0a's UI slot registry.
3. **Archive** (retained history, participation evidence only): `archiveManifest.ts` (what is included and why),
   `archiveReads.ts` (paged reads over the retained set), `archiveFinalization.ts` (seal the manifest, mark the archive
   immutable). Surface: `server/src/components/co-managed/CoManagedArchive.tsx`,
   `server/src/app/msp/co-managed/archive/page.tsx`, and the bytes route
   `server/src/app/api/co-management/archive-files/[archiveFileId]/route.ts` — an authenticated 404-by-default route that
   reuses L4a's file-stager rows rather than copying blobs. It declares itself in L0a's public-route manifest; middleware
   itself is L0a's (see §3).
4. **Lapse**: `packages/licensing/src/lib/co-managed-lifecycle.ts` gains the `terminated` / `read_only` / `grace` states
   (the file is created by L0b; this card adds 8 lines). Grace is a durable deadline computed from
   `lapse_started_at`, not a wall-clock wait, so the guide injects it via fixture.
5. **Enforcement through L0c, not through surfaces**: register the lifecycle resolver into L0c's write-admission choke
   point so a read-only relationship refuses native writes; propagate the resulting `workspaceReadOnly` flag from
   `getCoManagedOperationalState` into `server/src/app/msp/tickets/page.tsx` (+10) and
   `server/src/app/msp/tickets/[id]/page.tsx` (+9) so the UI stops offering write controls. Those two pages are shared with
   L3b2 (35–42%) — hunk-level only, and the read must be a cached capability read (R4).
6. **Tenant deletion / portability coverage**: extend `ee/temporal-workflows/src/activities/tenant-deletion-activities.ts`
   (+6, **main-changed: YES**) and `ee/temporal-workflows/src/workflows/tenant-deletion-workflow.ts` (+15) so closures,
   manifests, retained archive rows and any in-flight restore uploads are deleted/merged with `hasTable` guards.
7. **30-day durable intake deadline, last and splittable** (card: "Lapse 30-day durable deadline across all background
   intake is in scope, last, splittable"). Lapse v1 is "block growth plus read-only on co-managed surfaces" (H §2 L7
   excluded list); the deadline adds deferred-intake processing once on renewal.
   **Split out of this draft (see Charter C5):** there is no durable co-managed intake/queue table to reuse and a column
   in the two closure/manifest migrations would not make one, so building it needs new intake infrastructure. A4 here
   proves grace → read_only → renewal restores writes; "deferred intake processed exactly once" is unproven.

- A7 Recorded guide: baseline links → end relationship → old URLs deny immediately → customer keeps everything → MSP opens

## 5. Risks

- **R1 double release**: closure retried by the workflow, the action, or an operator. Mitigation: unique
  `(tenant, relationship_id)` on the closure row and a release that is an update-if-null inside one transaction, not a
  read-then-write.
- **R2 archive over-sharing**: deny-lists leak as new message kinds appear. Mitigation: allowlist by evidence class, with
  A2 asserting absence as well as presence, and the manifest recording exclusions by class (as H §2 L7's export bar does).
- **R3 read-only gaps**: enforcement at the UI only would leave actions and REST writable. Mitigation: L0c is the single
  choke point; the pages only reflect `workspaceReadOnly`; A3 iterates the gate registry.
- **R4 hot path**: `getCoManagedOperationalState` in a list page is the exact shape PLAN §3 forbids per request. Mitigation:
  one cached participation read per request at most, zero for psa tenants, and the budget snapshot as the gate — raising it
  is a reviewed diff.
- **R5 licensing regressions**: `resolveSelfHostEffectiveTier` must not default to `essentials` on error nor require co-managed tables (DO-NOT-PORT #14); new states extend the lifecycle file, not tier resolution.
- **R6 tenant deletion**: `tenantTableMetadata.ts` and the activities are shared, main-changed hot files; and the deletion
  path must not need the new tables to exist for a non-participating tenant.
- **R7 i18n**: departure and archive strings need a namespace under `server/public/locales/en/msp/` plus all locales and `xx`.
- **R8 authority to end**: only a party entitled to end may end. Reuse L1a's relationship authority rather than a new
  permission; check it in the action, and let A1 cover the refusal case.

## 6. Open design choices

- **What "released exactly once" means for a seat** (leaning: allocate-on-admission, release-on-closure with an
  `allocation_released_at` stamp, so the pool ledger is auditable without a second table).
- **Archive lifetime** (leaning: retained until tenant deletion, read-only, no expiry in v1 — an expiry needs a retention
  policy owner this card does not have).
- **Grace length** (leaning: 30 days; stored as a durable deadline on the lapse row, not a wall-clock wait).
- **Whether the departure UI blocks on an outstanding handoff** (leaning: warn, do not block). Reason: the user is leaving;
  blocking on another party's inaction would trap them.
- **Decided, not open**: lapse v1 = block growth + read-only on co-managed surfaces, retained-command admission out of
  scope (H §2 L7); no archive byte copy (L4a); no middleware matcher edit (L0a).

## Repair round (draft-review defects)

**Defect 1 — read-only ticket detail.** `CoManagedLocalTicketDataSourceProvider` now composes `screen: { readOnly: true }`
when the workspace is ended or lapsed (merged over the native screen by `composeTicketDataSource`). That is the existing
seam: `TICKET_SCREEN_FIELDS` freeze every field and `TICKET_WRITE_ACTION_CAPABILITIES` (delete, duplicate, template,
workflow, project task, quick invoice, category create) are forced off. Composer/reply/edit, description editor,
agents picker and watch list already read `dataSource.screen.readOnly` (or the frozen-field list). Writable workspaces
are unchanged (the override is omitted entirely). Not covered: ticket detail opened from client/contact drawers does
not pass through the provider; the write choke point still refuses there, but the controls are not hidden. Reported, out of scope.

**Defect 2 — archive files / time entries: no real producer, so SPLIT OUT (not faked).** Evidence on this branch and
`origin/main`: no writer inserts `time_entry` into `co_managed_participation_evidence` and its `source_type` CHECK
(`20261030100500/100501`) rejects the value; no retained-file table exists (L4a/L5 on main only add `co_management_deliveries`,
an outbound delivery ledger). Time the MSP recorded already lives in its own `time_entries`, not in the customer's data.
Therefore: `time_entry` removed from `ARCHIVE_EVIDENCE_CLASSES` and from the `privateParticipationEvidence` special case; no third
migration. `registerCoManagedArchiveFileSource` stays as the documented extension point; the bytes route and manifest are
honestly empty until a source registers. The DB test with a registered source is a contract test of the registry only.
**Split out:** archive files -> L4a (retained-file store) owns registering a `CoManagedArchiveFileSource`; archive time
entries -> a future time-evidence card (needs a producer plus a widened source_type CHECK migration).
