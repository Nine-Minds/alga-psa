## 1. Intent

Responsibility is a durable state machine, not a status field. A customer escalates a ticket to the MSP with a shared note;
the MSP becomes responsible, the ticket appears in its **Working** queue with the customer's own statuses and a workspace
label, and the MSP hands it back — each transition carrying an operation id, an expected revision and an immutable receipt.
Take-back and grant revocation are the customer's mirror moves. This card is the engine and the queue: the domain commands,
the authorized reader that the list and every count share, the ticket-edit path that lets a technician work the shared ticket
through the native writer, and the URL contract for `/msp/tickets/customer`. Screens belong to L3b2; the conversation to L4a.

- **Conversation/comments on shared tickets**: L4a (`ticketCommentWriter`, audiences, attachments) and L4b (disclosure). H §2

- **SLA clocks** L6b; **time/effort** L6a1/L6a2; **events and delivery** L5; **tasks** L3c; **policy and delegated
  administration** L2 — imported, not re-implemented.
- **Dropped, not deferred**: legacy `queueView`/`/msp/co-managed/tickets` redirects. `queueView` has **zero occurrences in
  base** (`git grep` verified on `~/alga-psa`), i.e. the URLs never shipped (PLAN §1; H §2 L3 Excluded). Keep the pure
  normalisation inside `ticketListScope`; ship no redirect adapter.
- **Bulk handback is plain**: PLAN §6.4 — "plain bulk handback, with no intent-recovery machinery". Per-row outcomes, no
  client-side recovery journal. (Its **UI** is L3b2's.)

## 4. Acceptance

- **A1** State-machine unit tests: escalate, hand back, take back, revoke; stale revision ⇒ `HANDOFF_CHANGED`; replay of the
  same `operationId` returns the original receipt and writes nothing; second escalation without a transition ⇒
  `ALREADY_RESPONSIBLE`; destination board inactive ⇒ `DESTINATION_UNAVAILABLE`.
- **A2** Receipt immutability and idempotency: `command_receipts` and `ticket_handoffs` are append-only in app code (no
  triggers — Citus skips them).
- **A3** Queue reader: Working vs Oversight, workspace unavailable (never widen to `all`), duplicate ticket-number search,
  pagination, and `signals` equal to the row counts under `{ signal, state: 'open' }`.
- **A4** Hot-path budget: the ticket update path costs **0** extra queries for a psa tenant (the branch costs 3 `readState`
  admissions per update; the L0 fast path must absorb them), and `FOR UPDATE`/`FOR SHARE` lock counts rise only for
  participating tenants. Needs the L0g harness — **this card cannot demonstrate the lock assertion without it**.
- **A5** Native-writer equivalence: a shared edit goes through `updateTicketInTransaction` with the same guards as native
  (close rules, bundle propagation), asserted by the unit tests for `coManagedTicketEditActions` / bundle utils.
- **A6** Recorded (H §2 L3, the parts this card owns): step 2 escalate with note + history entry, step 3 Working list /
  Oversight toggle / duplicate-number search, step 5 status+assignment persist across reload and a stale edit conflicts, step
  6 hand back, step 7 take back leaves the queue. Steps 1, 4, 8, 9, 10 are L3b2's / L3c's. Fails the card if judged on them
  (PLAN §4: "Smoke and review judge only the card's own bar").
- **A7** Gates: migration lint, upgrade-order N-1, schema-absent neutrality (board-move/delete probes are fail-closed on
  missing tables — must use the L0 fast path), tenant-manifest coverage, generated artifacts.

## 5. Risks

- **R1 main-changed shared files**: `optimizedTicketActions.ts`, `ticketBundleUtils.ts`, `tenantTableMetadata.ts`,
  `tenant-deletion-activities.ts`, `tickets/src/lib/index.ts`, `ticket.interfaces.ts`, `i18n` test. Hunk-only 3-way apply;
  diff against main; never whole-file restore.
- **R2 locks in `updateTicketInTransaction`**: take `FOR UPDATE`/`FOR SHARE` **only** for participating tenants and prove it
  with the budget's lock count; an unconditional lock is a psa hot-path regression (PLAN §3).
- **R3 bundle propagation**: `assertBundlePropagationAuthority` is 202 added lines of close/master/child rules. Dropping it
  lets a collaborator propagate a board-scoped status across bundles; port it whole and test the refusal cases.
- **R4 ambiguous commit**: `saveSharedTicketEditAction` returns `unknownOutcome` on connection loss and keeps the request id
  and baseline for an exact retry — never claim rollback. Test that path.
- **R5 idempotency keys**: the fingerprint must cover actor + resource + transition + request, and must not include mutable
  state, or a legitimate retry becomes `HANDOFF_CHANGED`.
- **R6 duplicate ticket numbers across workspaces**: every row, export column and deep link carries
  `workspace_tenant`+`relationship_id`; the identity key is lower-cased and prefixed `shared|native`.
- **R7 cross-tenant references**: MSP reference rows have no cross-tenant FK by design; deletion/export metadata must list
  them (tenant-manifest gate) or a deleted customer strands routing rows.
- **R8 test port**: do not port `coManagedBootstrap.integration.test.ts`; write focused per-card tests (PLAN §1).

## 6. Open design choices

- **Working vs Oversight — decided** by H §2 L3 step 3 and the reference reader: Working = tickets the MSP is responsible
  for; Oversight = board-scoped read that includes customer-handled tickets. Dormant under `escalation_only`.
- **Native MSP rows in Customer Tickets — decided: no.** `ticketListScope`'s own header (reference) says "there is no 'This
  MSP' workspace"; the reader is the qualified relation only, and the page redirects a native-scope URL to `/msp/tickets`.
- **Signals — decided** as reader filters (`escalated_unassigned`, `awaiting_reply`) so counts cannot drift from rows; a
  denormalised counter would be a second source of truth.
- **Bulk handback atomicity — leaning: per-row outcomes, best-effort, no all-or-nothing.** PLAN §6.4 forbids recovery
  machinery; a partial failure must be visible per row and each row is independently idempotent. Open only on whether the UI
  blocks a second attempt (L3b2's call).
- **Assignment before escalation — decided: keep** (its own migration): a technician pre-assigns the destination team so an
  escalation does not land unowned; the queue's `escalated_unassigned` signal still catches the rest.
