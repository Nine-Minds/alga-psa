# CM L8a — Capacity purchase (Stripe) & licence claims (design session plan)

Reviewer question: "Can an MSP buy co-managed capacity without a double charge or capacity granted before payment is verified
— and can a self-host install prove the same from a signed claim?"
Authority: `~/cm-redelivery/PLAN.md` (wins), `manifests/L8a.md` (binding), `H-guides-deploy.md` §2 L8, §4, §5.

## 1. Intent

Buying capacity is a durable **operation**, not a checkout callback. The sponsor reviews a quantity and an amount, an
operation row is written before Stripe is contacted, and capacity only moves when the provider's reconciled state is verified
— a replay is a no-op and an abandoned checkout offers **Resume** rather than a second charge. The new subscription is
identified by `metadata.subscription_kind=co_managed` and is never the MSP's own Pro item; a reduction below allocated seats is
refused. Self-host installations prove capacity from a signed licence claim bound to the tenant (`aud`), not from a purchase.
This card also carries the upgrade purchase whose *closure* belongs to L7a and whose restored-workspace acceptance belongs to
L8b.

## 2. What changes (in this order)

- **L7a** owns departure/closure and the allocation release; the upgrade *purchase* is here, the closure is not.

- **Self-host claims**: PLAN §6.4 — "self-host licence claims (L8a; blocked-external, since the issuer lives outside this

## 4. Acceptance

- **A1** Webhook idempotency: replaying `customer.subscription.*` twice leaves capacity and the operation row unchanged; the
  receipt proves the second delivery was a no-op.
- **A2** Capacity granted only after verification: the checkout return path grants nothing; only a reconciled, paid, active
  co-managed subscription raises capacity, and a brand-new subscription starts at `capacity: 0`.
- **A3** Subscription-kind isolation: `metadata.subscription_kind=co_managed`; the MSP's Pro items are untouched (assert on the
  Stripe payload, and that base-Pro price ids are never in the co-managed item).
- **A4** Licence claim verification: a token with `aud` ≠ tenant or tier ≠ pro is refused; an expired token is refused at
  point-in-time even though `verifyLicense` caches valid results (`verify-license.ts` says callers must re-check `exp`).
- **A5** Reduction floor: buying below allocated seats is refused with `ALLOCATED_CAPACITY_REQUIRED`; one in-flight operation
  at a time; a different quantity on the same operation is `OPERATION_CONFLICT`.
- **A6** Recorded: H §2 L8 steps 1–6 and 8 on staging with the Stripe emulator / test mode. **Step 7 (self-host claim) and a
  live production price are blocked-external** — the guide records the mechanism with a CI-only test signing key (H: "Self-host
  uses a test signing key in CI only") and says plainly that production flag-on waits for the real price id and issuer.
- **A7** Gates: migration lint, upgrade-order, schema-absent neutrality, image-boot isolation (workers must boot if
  `@alga-psa/co-managed` fails to resolve), generated artifacts, tenant-manifest coverage for both new tables.

## 5. Risks

- **R1 currency and price hardcoded** — the reference has `CO_MANAGED_MONTHLY_SEAT_CENTS = 1149` and
  `price.currency !== 'usd'` in `coManagedSubscription.ts:assertCoManagedPrice`. That breaks AGENTS.md ("Do not hardcode
  currency types") and H §2 L8 step 1 ("rendered with the standard currency components; no literal 'USD'"). Mitigation: the
  configured `STRIPE_CO_MANAGED_USER_PRICE_ID` price object is the single source of amount and currency; render with
  `useFormatters().formatCurrency` (verified in base: `packages/ui/src/lib/currency/useCurrencyFormat`); the constant survives
  only as emulator fixture data.
- **R2 webhook hot path** (DO-NOT-PORT #15): the branch queries `co_managed_entitlements` after **every** webhook and fails the
  event when the table is missing. Mitigation: capability/participation admission first, `hasTable`/registry guard, and a test
  that a webhook for a psa tenant issues no co-managed query.
- **R3 tier resolution** (DO-NOT-PORT #14): `resolveSelfHostEffectiveTier` returning `'essentials'` on any error can downgrade a
  hosted Pro JWT; `upsertLicenseState` has a 60s `iat` skew failure and requires co-managed tables. Do not port as-is.
- **R4 emulator escape**: `stripeApiOverride` must stay loopback+`sk_test_`-only in production review and default to real
  Stripe; a non-loopback HTTP endpoint is refused (verified in reference). Add a test for the production refusal.
- **R5 double charge / capacity before payment**: guarded by A1/A2/A5; the failure mode is a second checkout for the same
  intent, so the operation id comes from the client once and is frozen across retries.
- **R6 tenant vs installation licensing**: a staged tenant claim must not alter installation mode, product identity or
  sponsorship capacity (`activateTenantPsaLicense` comments); a test asserts the singleton `license_state` row is untouched.
- **R7 migration dating and guards**: branch timestamps precede main's; re-date, `IF NOT EXISTS` on the unique index, and
  `CREATE TABLE` only (no ALTER on existing tables) so lint passes without an allowance.

## 6. Open design choices

- **Price/amount source — decided**: configuration (`STRIPE_CO_MANAGED_USER_PRICE_ID`) is the only source; missing config means
  the entry points are absent and the gate registry treats them as gated (H §2 L8 deployment). This forces the R1 fix rather
  than leaving it open.
- **Absolute pool target vs delta — decided**: the operation carries the absolute quantity (reference
  `runCoManagedPurchase({ quantity })`, H step 5 "an absolute pool target"), which makes the allocated-seat floor checkable.
- **Self-host claims timing — open, leaning: ship verification + guard now, defer enablement.** PLAN §6.4 calls it
  blocked-external; the mechanism can land behind self-host licensing without a production issuer, but flag-on must wait. The
  session should confirm whether the guide records it at all.
- **Payment-failure retention — leaning: keep the retained row** (`retain_co_managed_payment_failure`) so a failed attempt is
  recoverable and auditable rather than silently dropped; the retention window is a session decision.
- **Decided by authority**: no production price in this card (blocked-external); no degradation/recovery matrix (F019–F026).

## 7. Review follow-ups (decided)

- **Operation completion is scoped.** A paid reconciliation completes only an in-flight operation whose
  `provider_reference` is the reconciled subscription, or (checkout-created) whose `operation_id` equals the subscription's
  `metadata.operation_id`, and whose `quantity` equals the reconciled capacity. A base-Pro renewal routed through the
  sponsor-base handler therefore cannot close an unrelated purchase.
- **A pool that was never paid for gets no grace clock.** `neverActivated(row)` (hosted, no lapse, `valid_until <= verified_at`,
  i.e. still the row created at capacity 0) suppresses the lapse stamp in `materializeState` while nothing is allocated; reconcile
  judges it on the row *before* the observation, so a pool that WAS active and lapses still gets its deadline. There is nothing to
  keep writable for a pool that never opened; the clock starts only after a verified active observation.
- **Checkout returns to the pool editor, not the overview.** `/msp/co-managed` is entitlement-gated (`admits`), so a first
  purchase whose webhook has not landed would 404 after a redirect-based payment. The session uses
  `redirect_on_completion: 'if_required'` (card payments finish in the dialog) and `return_url` `/msp/account#account-co-managed`,
  where the editor re-reads the pending operation and offers Resume. The return path still grants nothing.
- **One governing self-host licence record.** `getEffectiveSelfHostLicenseInput(tenant)` (own staged claim, else the installation
  row; claim-lookup failure = no claim) feeds both `resolveTenantTier` and `checkApplianceLicenseSeatLimit`, so a workspace cannot
  be tiered by its own claim and metered by the installation's. With claims disabled both are byte-for-byte main's queries; the
  installation licence keeps its unbound seat check.
- **Stripe emulator serves products.** Prices reference a product, and the MSP's own subscription handler resolves
  `price.product` by id (`ensureStripePriceRecord`), so `GET /v1/products/:id` is part of the emulated surface (seeder `product`,
  state view `products`), not a smoke-time shim.
- **Self-host claim staging is split (deliberate).** The verifier, the tier/seat guard and the AI-credential guard ship dark behind
  `ALGA_TENANT_LICENSE_CLAIMS=enabled`. `activateTenantPsaLicense` has no product caller yet: the License-page submission path
  (`licenseManagementActions` scope routing, `TenantLicensePanel`, `LicenseBanner`) waits for the external issuer (PLAN §6.4,
  blocked-external) and is the splittable remainder of this card.
