# L0c — Write-admission choke point

## Production review composition

The review launcher may preload a process-local CommonJS module before the server
starts, using `NODE_OPTIONS=--require=/absolute/path/to/review-reader.cjs`. The
module sets `globalThis.__algaCoManagedReviewReader` to an object containing a
single `tenant` and a `readState(db, tenant)` function. The server installs that
reader through `installCoManagedWriteAdmission({ readState })`, scoped to that
tenant; other tenants retain the independent default. The selected tenant must
have product code `co_managed` in the isolated review database. Installation
invalidates its cached product hint. The reader must be lock-free. The fixture
module and its tenant ID belong outside the repository.

Remove the preload and restart the review service to remove the fixture. The
ordinary server has no review reader configured. Production still ignores
`CO_MANAGED_DEV_FORCE_STATE` and `devForcedStates`, and
`FORCE_CAPABILITIES=co-managed:off` bypasses the review reader. This composition
does not implement L7a lifecycle computation.

Reviewer question: "Can co-managed lifecycle states (read-only, terminated, lapse) refuse native writes through ONE choke point, at zero cost for normal tenants?"

Base: `main` @ 058d45c388 (this worktree). Implementation rebases onto `main` after L0a and L0b merge: neither is present in this base, so every L0a/L0b-owned path below is a contract, not a file I can read here.
Reference: `feature/co-managed-it` @ 2d00cb6f0e (base 7e8d87a948).

## The decision

Admission lives in `packages/db`, on the tenant-scoped write builder returned by `tenantDb()`. `tenantDb` is the one function every tenant write already passes through — 7,352 call sites in 1,956 files against 2,107 `withTransaction` sites in 439 files. A transaction-level hook would miss writers that open their own transaction (asset writes use `knex.transaction` directly, `packages/assets/src/actions/assetActions.ts:1300`), and a call-site hook is the 322 sites this card exists to delete.

Two properties make it free for a plain PSA tenant:

- The guard is only attached when the tenant is *not known* to be a non-participant. A resolver answers `tenants.product_code` once per process per tenant; a negative answer is permanent (a tenant is created co-managed or not, and only ever leaves that product), so a PSA tenant runs today's builder with no wrapper, no extra query, no extra transaction.
- Reads are untouched. `tenantDb.table()`/`scoped()` are used by both reads and writes, so the guard rides the write *terminals* (`insert`, `update`, `del`, `delete`, `truncate`, `increment`, `decrement`) and reads the table name the builder already parsed.

Admission here means *refusal*, not the lock-ordered operational transaction. L0b's `assertCoManagedOperationalWrite` / `withCoManagedOperationalTransaction` stay the primitive for the handful of paths that must serialize with acceptance, allocation and termination (L1a, L7a). The choke point never takes `FOR UPDATE`.

**Split decision: retained-command admission does not ship in this card.** A retained command is a *grant* of permission to write into a read-only workspace (the MSP appends an appointment to a customer calendar, schedules a comment, imports a KB article). Split it because the default already fails closed: with L0c alone, a retained command on a read-only workspace is refused, which is safe. Shipping the carve-out here would mean designing the exception before the state machine that grants it exists (L7a), and it would put scheduling, Teams and KB write paths into review alongside the choke point. The board already scopes this as splittable (PLAN §6.4). Until L0c-b, the four surfaces are listed in the operational table registry so their writes are refused rather than silently allowed.

## 4. Flag gating points

The choke point is not a rollout gate; it is state admission. Registration is unconditional so that a flag flip needs no restart, and the decision tree never reaches PostHog:

| Entry point | Adapter | Decision |
|---|---|---|
| Any tenant write through `tenantDb` | `admitTenantWrite` | allow / throw the resolver's denial |
| Inherited `BaseService` mutations (`create`, `update`, `delete`, `bulkCreate`, `bulkUpdate`, `bulkDelete`, `mutationTransaction`) | default `mutationGuard` | same function |
| `insertParentScoped` | explicit `await` before the parent pre-check | same |
| REST, server actions, client portal, credentials | error mapping only (§ table below) | refusal rendered in the surface's own shape |

The resolver's first read is `tenants.product_code`, and it must also honour the forced capability value: with `FORCE_CAPABILITIES=co-managed:off` the resolver answers `canWrite: true` for every tenant, so the kill switch turns admission off without a deploy. That keeps the guide's Chapter N honest, and it keeps a broken co-managed package from freezing writes in an appliance (`PLAN §2`: workers and images must boot when `@alga-psa/co-managed` does not resolve).

### Error mapping

| State (`CoManagedLifecycleError.lifecycle.state`) | REST `/api/v1` (`handleApiError`) | Server action (`withAuth`) | Client portal (`ClientTicketActionError`) | Credentials (`CredentialSaveResult`) | Worker / outbox |
|---|---|---|---|---|---|
| `active`, `grace`, `independent` | write proceeds | — | — | — | — |
| `pending_acceptance` | 409, `code: CO_MANAGED_NOT_ACTIVE` | `{actionError, messageKey: 'common:errors.coManaged.acceptancePending'}` | same payload | `{ok: false, code: 'CO_MANAGED_NOT_ACTIVE'}` | throws; L0b's inbound processor defers |
| `read_only` | 423, `code: CO_MANAGED_READ_ONLY` | `{actionError, messageKey: 'common:errors.coManaged.readOnly'}` | same payload | `{ok: false, code: 'CO_MANAGED_READ_ONLY'}` | skip before SQL |
| `terminated` | 423, `code: CO_MANAGED_READ_ONLY` | as `read_only` | as `read_only` | `CO_MANAGED_READ_ONLY` | skip |

The status codes are the reference's (`423 Locked` for a read-only workspace is the meaning the branch chose and the one every guide already expects). Three consequences fall out of the shapes rather than from new code:

- `withAuth` returns the payload instead of rethrowing, because Next.js strips thrown messages at the serialization boundary (`packages/ui/src/lib/errorHandling.ts:61-62`), and returning from inside `runWithTenant` lets `localizeActionError` (`packages/auth/src/lib/localizeActionError.ts:65`) translate the `messageKey` like any other action error.
- `toClientTicketActionError` recognises the refusal so `expectedOrThrow` (`client-tickets.ts:131`) does not log an expected outcome as a server fault.
- `credentialSaveFailure` recognises both codes before its `logger.error` line, for the same reason.

## 11. Risks taken knowingly

1. **A best-effort `catch` can swallow a refusal.** The seven representative public paths have behavioral propagation coverage. Other best-effort pipelines still need domain-specific review when their behavior is changed.
2. **The TTL window.** A decision is cached for 5s per process, so a workspace terminated at `T` can accept a write until `T+5s`. The lock-ordered termination path (L1a/L7a) is the authority; states that must be exact use the primitive, not the choke point. `invalidateWriteAdmission(tenant)` is called by the in-process transition actions and is best-effort across replicas.
3. **Escape hatches.** `builder.clone()` returns a fresh builder, `trx.raw('UPDATE …')` bypasses everything, and `unscoped()` is deliberately unguarded. Clone is re-guarded; the other two are the coverage gate's job, not the runtime's.
4. **The operational table list is a positive list.** A forgotten table means a silent *under*-refusal for a co-managed workspace — the safe direction for delivery, the wrong direction for the feature. A4's seven surfaces are the regression net; every later card that adds a native write surface must add its tables.
5. **Co-managed tenants pay a lifecycle read per TTL window per process**, and `readState` as the reference wrote it takes `FOR UPDATE` on the sponsor's entitlement row. The resolver must call the lock-free cached variant, or a read-only workspace's remaining reads and writes will contend on the sponsor's row.
6. **`withAuth`'s return type widens** to `TResult | ActionMessageError`. Callers that treat any returned object as data would need to check; the existing `unwrap*ActionResult` helpers already do.
7. **Registration is a boot-time import.** A missing install fails open (writes allowed) rather than closed. Import resolution is checked by typechecks and worker builds; deployment smoke must verify each running process installs the resolver.
8. **`tenants.product_code` is read with `unscoped('…')`** on the lookup, as `tenantSuspension.ts:8-14` already does, so the read is not tenant-filtered by construction. It is keyed on the tenant id and returns one row.

## Amendment (post-rebase)

Recorded after rebasing on origin/main, where L0a and L0b have merged. Where this section and the sections above disagree, this section wins.

### What L0b already shipped
`packages/db/src/lib/writeAdmission.ts` exists with `registerWriteAdmissionProvider`, `admitWrite` and `resetWriteAdmissionProvider`, two consumers, and `writeAdmission.test.ts`. L0c **extends that file**. There is no parallel module, and L0b's exports and tests are unchanged.

### Reconciled API: two seams, one decision path
- **Provider** (L0b): exact, in-transaction, follows the owner's lock order. Unchanged.
- **Resolver** (L0c): `registerWriteAdmissionResolver((db, tenant) => Promise<{ canWrite, denial? }>)`. Lock-free, cached for `WRITE_ADMISSION_TTL_MS` (5s), clearable with `invalidateWriteAdmission(tenant)`. Both seams live on `globalThis` (`__algaWriteAdmissionProvider`, `__algaWriteAdmissionResolver`, `__algaWriteAdmissionState`).
- `admitWrite` consults the resolver first and then the provider. `admitTenantWrite(db, tenant, { table?, operation })` is the transaction-free entry used by the `tenantDb` terminal guard and the `BaseService` default `mutationGuard`.
- They stay separate because the resolver may be up to a TTL stale and must never lock, while the provider must be exact.
- Cost model: with no resolver registered, no guard is attached and ordinary writes issue no admission SQL. Direct `admitTenantWrite` calls without registration warn once per tenant. With a resolver, a non-`co_managed` product lookup goes into a permanent negative Set, and `tenantDb` then attaches no wrapper; authenticated PSA sessions can seed that set without a lookup. Co-managed decision refreshes recheck the product before invoking the lifecycle reader. A failed product lookup fails open and is not remembered.
- `packages/db` never imports licensing. The registering package builds the denial (`CoManagedLifecycleError`).

### Merged-reality differences from the plan
- `BaseService` already has `mutationGuard`; its default now calls `admitTenantWrite` for operational tables.
- `CoManagedLifecycleError` / `isCoManagedLifecycleError` live in `packages/licensing/src/lib/co-managed-lifecycle-error.ts`; `coManagedRefusalMessageKey` is added there.
- `hotPathQueryBudget.json` is unchanged from main. Its harness installs the resolver and drives the real authenticated PSA path. `CM_L0C_REVIEW_ROLLOUT=off|on` controls the release flag with eligibility false; both compare to the same snapshot.
- `FORCE_CAPABILITIES` is parsed by `forcedValue(raw, 'co-managed')` from `@alga-psa/core/capability`; `off` and `malformed` both disable admission.
- Workers cannot resolve licensing through `src/*` path maps, so `packages/licensing/src/co-managed-write-admission.ts` is a barrel and the package gains a `./co-managed-write-admission` export. `services/email-service/tsconfig.json` gains the matching path.
- `packages/auth` and `packages/client-portal` now depend on `@alga-psa/licensing` (package.json and lockfile).
- The `product_code` value for a co-managed tenant is assumed to be `co_managed`. The current CHECK constraint allows only `psa`/`algadesk`; widening it is a migration owned elsewhere (none here).

### Known gaps at the post-rebase checkpoint (superseded by the review amendment below)

### Review amendment: cold read, runtime holes, real-path A4, dev reader

- **Cold `tenants` read removed (A2).** `server/src/instrumentation.ts` installs the resolver in every web process, so without a seed a PSA tenant's first operational write per process would add one `tenants.product_code` read. `getCurrentUser` now calls `noteTenantProductCode(tenant, session.user.product_code)` (a seam in `packages/db`, no licensing import). Known PSA and AlgaDesk codes go straight to the permanent negative set, so a PSA request through `withAuth` / `runWithTenant` pays zero reads. Workers (no session) still pay one read per process per tenant. The hint is ignored for a tenant that has been invalidated and not yet re-read (`mustLookup`), and never overrides a decision already made.
- **Runtime holes.** Former exempt raw writes use `await admitOperationalWrite(db, tenant, table, operation)` before execution. The helper checks `isOperationalWriteTable(table) && isTenantWriteGuarded(tenant)` first, so a PSA tenant pays no SQL. `tenantDb.insertParentScoped` and the `BaseService` default guard use the same helper. A6 requires an immediately preceding admission against the same connection for an escape write, and fails exemptions that claim to be uncovered. The parent-scoped engine has one documented exemption because it admits before parent validation.
- **BaseService composition.** The default admission runs first, then the caller's `mutationGuard`; a caller cannot opt out of admission.
- **A4 drives the real write path.** Credential: real `nativeCredentialSource.update` over the recording fake knex (no UPDATE, no `logger.error`, `{ok:false, code}`). Client portal: real `Comment.insert`. REST: a thrown `CoManagedLifecycleError` through the real `handleApiError` gives 423/`CO_MANAGED_READ_ONLY` and 409/`CO_MANAGED_NOT_ACTIVE`.
- **Dev/test-only forced state.** See section 7. Option `devForcedStates` on `installCoManagedWriteAdmission`, env `CO_MANAGED_DEV_FORCE_STATE`. Dropped with a warning when `NODE_ENV === 'production'`.
- **Session product code and invalidation.** `PRODUCT_CODES` already includes `co_managed`, and the NextAuth JWT/session mapping preserves it. Null or unknown product codes still normalize to PSA, and an existing session may predate a product change. `invalidateWriteAdmission(tenant)` is per process, so a negative-set entry in another process persists until restart. Cross-process invalidation and lifecycle transitions belong to L7a.
- **Cache coherence.** The resolver's cache key tracks the parsed kill switch, so cached refusals do not survive switching it off. Invalidation also supersedes in-flight decisions; an older lookup cannot repopulate the cache after a transition.
