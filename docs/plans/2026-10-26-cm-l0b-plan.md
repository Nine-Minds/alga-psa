## 11. Design decisions

**11.1 The tenant manifest (Q1).** `packages/db/src/lib/tenantTableManifest.ts` declares one entry per tenant table:
`{ table, deletion: 'ordered' | 'excluded' (reason), scope?: TenantTableScope, export?: { rank }, citus?: 'distributed' | 'local' | 'unstated', clientKeyed?: boolean, references?: { table, column, onDelete, resolution?: 'null-before-delete' }, block?: string, note?: string }`. Declaration order is the authoring rank. `computeTenantDeletionOrder()` runs Kahn over the restrictive edges in `tenantTableForeignKeys.ts` restricted to manifest tables, with each table's legal placement validated against its rank; it returns `{ order, violations, insertions }`. Today `order` is element-for-element identical to the 549-name literal, which is the point: the array is a *golden projection* of the manifest, not a second source. New tables get a computed insertion point (`--place`), so L1a adds an entry and never edits the activity file. Cycle handling has two declared classes: (a) the eight FKs `breakCircularDependencies()` nulls before the loop are declared `resolution: 'null-before-delete'`, excluded from the DAG, and drive the prepass — a test asserts the eight source blocks match the eight declarations; (b) any residual cycle among restrictive edges raises `TenantManifestCycleError` naming the cycle, surfaced by `--check`, the validator, and the golden test — never at worker boot, because nothing on the runtime path calls the engine's error branch. Reconciliation with main's path (`ee/temporal-workflows/src/activities/tenant-deletion-activities.ts`, `deleteTenantData` line 1895) is: same table set, same order, same per-table `information_schema` discovery query, same `tenantDb`/`unscoped` boundary logic. The discovery query is deliberately *kept* even though the manifest could supply the column: removing it would change the statement count, and this card's bar is "identical", not "better". Removing it is a separate reviewed change with its own budget diff.

**11.2 Ownership transfer (Q2).** Each consumer stops owning a list: `tenant-deletion-activities` reads `tenantDeletionOrder()` (membership + order); `ee/server/src/lib/tenant-management/tenant-export.ts` reads `tenantExportOrder()` (48 names today, preserved by declared `export.rank`, removing `TENANT_TABLES_EXPORT_ORDER`); `packages/clients/src/lib/clientMergePlan.ts` keeps its four lists but a test asserts their union equals the manifest's `clientKeyed` set plus the declared audit exemptions, so a new client-keyed table fails until it is classified; Citus ownership is `supportsTriggers` plus the `citus` facet, consumed by later migrations only; `tenantTableMetadata` and `tenantDb.cjs` stay literals, cross-checked against the manifest by A5; maintenance fan-out gains the descriptor registry, not table facts. `scripts/validate-tenant-management.ts` keeps its DB FK check (the only ground truth for edges the snapshot may lag) and adds the manifest checks.

**11.3 Lifecycle hooks (Q3).** `packages/tickets/src/lib/ticketLifecycleHooks.ts`:
`registerTicketLifecycleHandler(kind, handler, options?: { onError?: 'isolate' | 'rollback' })` and
`dispatchTicketLifecycle(trx: Knex.Transaction, event: TicketLifecycleEvent): Promise<void>` where
`TicketLifecycleEvent` is a discriminated union of `resolved { tenant, ticketId, statusId?, actorUserId? }`,
`reopened { … }`, `awaitingClient { tenant, ticketId, previous, next }`, `beforeSourceChange { tenant, ticketId, fields, actorUserId? }`.
Call sites (none here, L0c adopts): ticket update paths for resolved/reopened/awaitingClient, and the pre-write retention
point for `beforeSourceChange`. Ordering: same transaction as the write; `beforeSourceChange` before the row write,
resolved/reopened after it, `awaitingClient` after the `response_state` write; handlers run in registration order.
Containment: default `onError: 'isolate'` — the dispatcher catches, logs `{kind, tenant, ticketId, handler}` and continues;
no handler error can escape into the native write. `'rollback'` exists for cards whose invariant is "the mirror must not
miss an event" (L4a/L5/L6b); this card registers zero handlers, and a test asserts the isolate path never propagates.

**11.4 Comment events and the eventBus extension point (Q4).** `commentEventRegistry.ts` exports
`registerCommentEventContributor({ name, retain?(trx: Knex.Transaction, { source, event }): Promise<boolean> })` and
`publishCommentEvent(trx: Knex.Transaction, source, event, native?)`; the event is discriminated on `source`: a ticket event carries `ticketId` and a `TICKET_COMMENT_*` `eventType`, a project-task event carries `taskId` and a `TASK_COMMENT_*` `eventType` (`@alga-psa/tickets` proves both are `EventType` members at compile time). When a contributor with `retain` is registered, `trx.isTransaction` is asserted before it runs. Semantics: contributors in registration order; the first `true` means the event
was retained in-transaction and native publication is skipped; no contributor (or all `false`) runs the caller's `native` closure, which is the call that was already at the site
(same calls, same order, same try/catch; no `registerAfterCommit` is added and nothing is wrapped in a new transaction). `TicketModelEventPublisher` extends the shared publisher and routes `publishCommentCreated`
through the same function. Native call sites that go through the registry: `commentActions.ts` (create, update), `client-tickets.ts`, `ticketModel.ts`, `taskCommentService.ts` (create, update). eventBus:
`packages/event-schemas/src/schemas/extensions/index.ts` exports `defineEventExtension({ name, eventTypes, payloadSchemas })`
and an `eventExtensions` tuple typed `as const`; `eventBusSchema.ts` composes
`EVENT_TYPES = [...CORE_EVENT_TYPES, ...EXTENSION_EVENT_TYPES] as const satisfies readonly [string, ...string[]]` and
`EventPayloadSchemas = { ...CorePayloadSchemas, ...EXTENSION_PAYLOAD_SCHEMAS }`; an extension name that collides with a core type or another extension fails `tsc` and throws at load (`assertEventExtensionsCompose`). With an empty tuple the inferred
`EventType` union and every schema reference are unchanged (A6 proves reference identity), and a later card widens the
typed union by editing only its own extension module and the one-line composition array.

**11.5 Job registration as data (Q5).** `JobDescriptor = { name, scope: 'tenant' | 'system', run, tenants?, concurrency?, includeSuspended?, schedule?: { cron }, capability?: string (tenant scope only), edition?: 'ce' | 'ee' }`, registered through `defineJob()`, which rejects duplicate names and malformed crons at import. Scheduler reads: `runMaintenanceJob` resolves `MAINTENANCE_JOBS[name] ?? descriptorMap()[name]`; `listMaintenanceJobNames()` returns native names first, then descriptor names; `isKnownMaintenanceJob` checks both; `defineJob` rejects names owned by a native job or native schedule (and `registerMaintenanceJob` rejects a descriptor's name); a `schedule` registers a row in `@alga-psa/types` that `setupSchedules.ts` (`listMaintenanceFanoutSchedules()`) and the CE converger (`resolveCeMaintenanceSchedules`) both read, filtered by `edition`; the module calling `defineJob` must be loaded by the scheduling process. A `capability` on a tenant job is honoured before fan-out: with no `registerJobCapabilityFilter` (L0a wires `filterServed`) the run is skipped before any tenant SQL, otherwise it runs only for served tenants. Empty descriptor list ⇒ identical name order, identical schedule array contents, identical fan-out SQL (the `includeSuspended` branch only changes the query when the flag is set, and no native job sets it).

**11.6 The write-admission primitive (Q6).** `packages/db/src/lib/writeAdmission.ts`:
`registerWriteAdmissionProvider(provider: (trx, { tenant, operation, resource? }) => Promise<void>)`,
`admitWrite(trx, ctx)`, `resetWriteAdmissionProvider()` for tests. `admitWrite` returns before reading `trx` when no
provider is registered, so an unregistered deployment pays one property read and zero SQL; a registered provider gets the
strict contract (must be inside a transaction). Adoption is separate because adoption is a *call-site* decision in 135
native files whose query budget only changes when a provider exists for that tenant: the engine cannot prove neutrality,
the call sites can, and bundling would couple a behaviour-neutral card to the largest rebase surface on the board (108
main commits) plus the T0 writer fixes that must land first.

**11.7 `admitWorkflowTagWrite` (Q7).** Lives in `shared/workflow/runtime/actions/businessOperations/shared.ts` next to
`throwActionError`, dispatches through `admitWrite(tx.trx, { tenant: tx.tenantId, operation: 'workflow-tag-write' })`, and
maps a refusal to an `ActionError` with the lifecycle code and `details.lifecycle_state`. With no provider it resolves
without SQL. L2 imports it from here, so L2's parent set stays `L1a` and does not include L0c.

**11.8 Neutrality (Q8).** See §12. "Identical" means: same statement count per step, same normalised statement text
(whitespace collapsed, bind placeholders kept as `?`), same lock-clause count (`FOR UPDATE`/`FOR SHARE`), and no table
name outside a snapshot taken at `058d45c388`. A reduction is a failure too, by construction.

## 12. Neutrality proof procedure (knex listener diff)

1. Snapshot at base: `git stash`-free worktree at `058d45c388`; run the seven scenario steps below through the existing
   integration harnesses, attaching a knex `query` listener that records `{ sql, bindings.length, trxDepth }`.
2. Scenario steps (chosen because L0b touches their code paths): `withAuth` request bootstrap (needs a running server; not
   recorded); ticket open (`TicketModel.createTicket`); ticket update with a status change (`TicketModel.updateTicket`); comment
   add (`createComment` action, plus `TicketModel.createComment`); comment edit (`updateComment` action), all driven
   directly against a fixture tenant with the event bus stubbed; maintenance-fanout tick for `expired-credits`; tenant deletion dry run
   against a fixture tenant (`deleteTenantData` with a non-management tenant).
3. Emit `{ step, count, statements }` to `hotpath.<sha>.json`; normalise by collapsing whitespace, lowercasing keywords,
   replacing literal UUIDs/ids with `?`, and sorting nothing (order matters).
4. Repeat at HEAD, diff with `node scripts/review/hotpath-diff.mjs` (checked in by this card; L0g replaces it).
5. Accept only when the diff is empty for every step. Query *reductions* and additions both fail; the test message names
   the step, the statement index and the delta.
6. Record the same run for Emerald (flag on, no participation) to prove the gate is not a second code path.
7. Startup cost is measured separately: `computeTenantDeletionOrder()` runs once per worker process at first use, with no
   I/O (the FK snapshot is a module constant). The activity's per-table statements are unchanged.

The listener hook is `knex.on('query')`; assertions live in
`ee/temporal-workflows/src/activities/__tests__/tenantDeletionQueryBudget.test.ts` and
`server/src/test/contract/hotPathQueryBudget.local.test.ts`.

## 14. Risks / open questions

- **Manifest rank is still authored.** The engine validates and places, it does not re-derive the 549 existing positions.
  A full re-derivation would reorder deletion statements for no benefit and would break the twelve source-text tests that
  read the file. Accepted; stated here so no one reads "computed order" as "regenerated order".
- **FK snapshot staleness.** `tenantTableForeignKeys.ts` is generated from a migrated database. If a migration adds a
  restrictive FK and the snapshot is not regenerated, the ordering check is blind to it. Mitigation: `--check` in CI
  against the migration smoke database. Whether that database is available to every CI job is **unverified**.
- **`validate-tenant-management.ts` runs against a live DB.** Whether it runs in CI today is **unverified**; if it does
  not, A3's DB half is manual and the golden test carries the bar.
- **Event type widening.** `EVENT_TYPES` composition relies on tuple inference from `as const` extension modules. If a
  later card declares a wide `string[]`, `EventType` silently widens and unrelated exhaustive switches stop failing —
  A6 plus a type-level test (`expectTypeOf`) guards the empty case, not the future one.
- **`includeSuspended` without a consumer** is dead code this card; it is ported because the descriptor shape needs it and
  the alternative is L4b/L5 editing the fan-out file. Reviewer should confirm that is acceptable.
- **`packages/licensing/package.json` export hunk** overlaps L0a's stated ownership of package exports; L0b takes the
  licensing subpaths, L0a takes `@alga-psa/co-managed/*`. If L0a lands first, rebase is textual.
- **Notification presentation and inbound-email registries** are in the reference's L0b manifest but not in this card's
  brief. They are declined, not forgotten; if the wave wants them, they belong to L5 with its delivery types.
