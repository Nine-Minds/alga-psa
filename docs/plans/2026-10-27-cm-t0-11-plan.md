## 4. Design detail where a wrong answer is expensive

**D1 — the metadata column.** Two halves, and both are needed or the fix is a no-op: the migration
must create `external_files.metadata` (`ADD COLUMN IF NOT EXISTS metadata jsonb`), *and* the
`FileStoreModel.create` path must stop dropping the field (today `updateMetadata` writes a column
that does not exist while `create` discards the value, so rows round-trip as `NULL`). The proof is
`storageService.workflowEvents.test.ts`-style: write metadata through the real model, read it back
from the database, assert the value — not a mock assertion.

**D3 — error fidelity.** The defect is not "`withAdminTransaction` throws"; it is that reading
`error.stack` can itself throw (`RangeError`, e.g. on a pathological stack) and replace the original
failure with an unrelated one. The guard must be *narrow*: a helper that tries to read `stack`/
`message` and falls back to `String(error)` — never a `try/catch` around the transaction body, which
would change which error the caller sees and could swallow rollback errors. The regression test
fakes an error whose `stack` getter throws and asserts the caller still receives the original error
(identity, not just message).

**X1 — the patch tripwire is the safety property.** The patch must fail `npm install` on any Next
version other than 16.4.2 rather than applying a string replacement that no longer matches. A
silently-mismatched patch is worse than no patch: it changes dev-only React internals with no test
covering the new shape. Keep the ancestry test (`next-flight-debug-ancestry.test.mjs`) as the
executable definition of "the patched shape is what we expect".

**X4 — tolerate one failure mode, not the step.** The apt 403 is third-party CDN flakiness. The
workflow change retries/skips *that* apt fetch and still fails the job if poppler is genuinely
missing. Do not delete the step, do not `continue-on-error` the whole step.

**X5 — one switch.** `dbReset`/`dbConfig` must honour `TEST_MIGRATIONS_DIR` exactly as the reference
does. The CE+EE overlay switch that sits in the same file is deliberately left out; taking it would
change which migrations the test database runs and silently widen this card's blast radius.

**Test helpers.** `fakeTenantDb` / `fakeQueryBuilder` are the substrate the transaction-threading
contract tests stand on: they must record the tenant filter and transaction handle actually used, so
a test fails when a query escapes its transaction or drops its tenant predicate. If a helper needs a
new capability to express that, extend the helper — do not weaken the assertion.

## 7. Risks and how this plan handles them

| Risk | Handling |
|---|---|
| X1 tripwire bricks `npm install` if main moves Next | Explicit in the PR body; the patch is version-pinned by design and the ancestry test names the expected shape |
| D3 turns into a broad `try/catch` that hides rollback errors | Narrow helper only; identity-asserting regression test |
| Shared-file hunks drag in another card's behaviour | Hunk-level ownership + `git diff 2d00cb6f0e -- <owned paths>` check before review |
| Migrations land out of order on the shared host database | Card is staggered T0-7 → T0-11 → T0-9a by captain order (2026-10-26); all are add-if-missing so a re-run is safe |
| X4 masking a real poppler breakage | Tolerate the 403 fetch only; keep the step and its assertion |
| Test helpers becoming a mock-shaped fiction | Helpers must record tenant filter + transaction handle; contract tests assert on the recorded values |
