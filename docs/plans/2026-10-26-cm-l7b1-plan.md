# L7b1 — Portable export engine: records & files (design charter)

Card 8c89765e. Reference `feature/co-managed-it @ 2d00cb6f0e`. Hard parents: L4a, L1b (PLAN §5, wave 5).
`packages/co-managed` itself is created by L0a (`manifests/L0a.md`: `package.json`, `tsup.config.ts`) — this card only
adds modules to it. **No migrations**: the manifest for this card contains no migration path.

## 1. Intent
When a co-managed relationship is being wound down (L7a) the customer must be able to take its own records and files
away as one self-describing package it can inspect offline: what was included, what was excluded and why, and digests
that prove the bytes. This card builds that engine — the archive format, the manifest and reference graph, the
record validator and identity model, the core record contributors (assets, work/projects, workflows, credentials vault),
blob staging and download — and it defines the **portable-domain contributor registry** so the remaining domains (time,
schedule, meetings, conversations, documents) can be added by L7b3 without touching the engine. Restore is explicitly
not here: L7b2 owns reading a package back.

## 3. Boundaries
- **No restore.** L7b2 owns `portableWorkspaceRestore*`, `restore-portable-workspace.ts`, restore receipts, the restore
  upload cleanup job and the `initializeApp` recovery call (DAG-REPORT R15 moves only the domain *exporters* out;
  restore stays with L7b2).
- **No domain contributors.** Time, schedule, meetings, conversations and documents move to L7b3 (DAG-REPORT R15:
  "The time, schedule, meeting, conversation and document exporters move to L7b3"). L7b1 must not import L6a1, L6c,
  L4b or L5 code.
- **No archive/closure tables.** L7a owns closures, archive files and manifests; L7b1 writes files, not tables.
- **No new tenant-scoped tables**, therefore no table-manifest or fanout rows here.
- **Excluded content** stays excluded by construction (H §2 L7: "export manifest exclusions (MSP-private, commercial,
  secrets)"). The vault is exported only as passphrase-encrypted material.
- No `release-v1-6-feature` references; no raw `useFeatureFlag('release-v2-0-feature')` (DNP #24, PLAN §2).

## 4. Acceptance
- A: the manifest is self-proving — every included entity has a digest and a reason, every excluded class has a named
  reason; the exclusions test is the manifest case in `coManagedPortableWorkspaceExportCases.ts`.
- A: contributor contract — a stub contributor and the asset contributor both round-trip through the registry; this is
  the test that de-risks L7b3.
- A: deterministic archive for identical input (stable ordering, no timestamps in digests).
- A: path safety — traversal and absolutised native paths rejected (`portableNativeFilePath`).
- A: flag-off — route 404, page `notFound`, action not-found; CE build renders the export page as unavailable.
- A: image-boot isolation — Temporal worker boots with `@alga-psa/co-managed` resolution forced to fail.
- A: hot-path budget unchanged for a psa tenant (this card adds no read to any native request path).
- A: no migration lint run needed; still run the schema-absent neutrality suite (nothing new to touch).
- R: export a workspace with a passphrase, download it, inspect the manifest; kill-switch chapter makes the entry point
  absent with data intact.
- Infrastructure honesty: the passphrase-encrypted vault path needs EE credentials configuration in the fixture; if the
  fixture cannot provide it, the case is recorded as not-run, not as passing.

## 5. Risks
1. **Under-designed registry blocks L7b3.** Five domains with different shapes (time rows, schedule recurrences, Teams
   meeting references, conversation threads with audiences, document versions) must all fit references/columns/export/
   retain/validate. Mitigation: Step 3 before Step 4, with a stub contributor that mimics a document-version graph.
2. **Memory and disk.** Archives stage bytes in a temp directory; base's tenant export builds the whole JSON in memory
   before upload. Set explicit size caps and stream; document the cap in the charter (H §2 L7 requires it).
3. **Worker boot coupling.** The `tenant-export-activities.ts` one-liner is the only place a failed co-managed resolve
   could take down the Temporal worker. Dynamic import, guarded, test-backed.
4. **Secret leakage.** Vault export must never emit plaintext tokens; the passphrase KDF and cipher parameters must be
   recorded in the manifest so L7b2 can restore without guessing.
5. **Transient-file recovery** (`portableTemporaryRecovery`) exists here but is only wired by L7b2. Until then it is
   dead-but-tested code — acceptable, but the charter must say so.
6. **CE/EE divergence**: the 4-line CE stub must return an unavailable shape the page understands; a `throw` in CE
   turns the MSP page into a 500 for every CE tenant (the gate-coverage contract does not catch this).

## 6. Open design choices
- **Decided (PLAN §5):** parent set L4a + L1b; the registry is L7b1's to define (PLAN §5: "export contributor registry
  (L7b1)").
- **Decided (DAG-REPORT R15):** domain exporters are not here.
- **Open — passphrase cryptography.** Reuse `ee/server/src/lib/credentials/encryption.ts` primitives (verified present in
  base) vs a purpose-built archive KDF. **Leaning** reuse, with the algorithm recorded in the manifest.
- **Open — transport.** Stream the archive from the app route vs reuse S3 presigned download as base's tenant export does.
  **Leaning** app-streamed with a size cap, because base's tenant export fails outright when S3 is unconfigured
  (verified in base: "S3 storage not configured - cannot store export") and a customer-wound-down workspace cannot
  depend on MSP storage configuration.
- **Open — relationship to the existing tenant export.** Wrap and supersede, or coexist? **Leaning** coexist: base's
  export stays for internal GDPR/tenant-management use, portable export is co-managed-scoped and passphrase-encrypted.
- **Open — v1 content width.** A-capabilities smell #8 suggests "records + files only". **Leaning** keep that: assets,
  work, workflows, core records, vault, files; no binary media.
