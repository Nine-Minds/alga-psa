Regenerate guide pages

Render to a temporary directory first. The renderer validates the supplied revision against the coverage file, requires all 14 guide rows, and writes completed recordings or blocked JSON and WebVTT scaffolds without changing these source files or fabricating WebM files.

node docs/guides/co-managed-it/render.cjs /tmp/co-managed-guides \
  --revision "$RECORDED_RUNTIME_REVISION" \
  --publication-revision "$PUBLISHED_GUIDE_REVISION" \
  --coverage /absolute/path/to/video-coverage.json

--publication-revision is optional and defaults to --revision. Use it for a later documentation-only publication: source links and the guide header use the publication SHA, while media validation and recording metadata retain the actual runtime SHA. It never promotes scenario acceptance.

The output directory represents the review packet's guides/ directory and contains the collection guide and 12 section guides. Coverage recordingPaths are relative to the packet root, so section artifacts must start with guides/. The renderer removes that prefix when writing them beneath the output directory. The main walkthrough is maintained in the review packet's root index.html and has its own recording artifacts.

Render a completed walkthrough

Coverage rows may use status: "complete" after the product interaction has been recorded and checked in a browser. Set testedRevision, recordedAt, durationSeconds, actors, steps, outcomes, and chapters. Set both playbackVerified and chapterSeekVerified to true. runtime must identify the same sourceRevision (or revision), and build.sourceRevision must match the candidate. recordingSourcePaths.webm and .chapterVtt point to files relative to the coverage JSON. The renderer validates the WebM container and duration with ffprobe, checks the timed VTT chapters, copies the media to recordingPaths, and writes a player with chapter seeking.

Blocked rows still need a blocker and a missing list. They must not claim a recording timestamp or verified playback/chapter seeking. To validate renderer behavior without product evidence, run node --test docs/guides/co-managed-it/render.test.cjs. That test creates a synthetic clip in a temporary directory. It is not a walkthrough and must not be added to acceptance evidence.

Review order and retained changes

For a full review, follow guides 1–9, then integrations, export and restore, and finally upgrade or departure on separate disposable relationships. Upgrade and departure end live trust; the active White Rabbit relationship supports the existing ticket review and should remain available.

Use a unique suffix such as CM-REVIEW-20261025-A for new records and messages. Record the account, organization, record link, initial state, action, result after reload, and any retained effect. Preserve sent messages, recorded time and financial evidence. Restore reversible settings to their original values.
