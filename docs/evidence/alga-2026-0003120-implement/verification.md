# Asset numbering implementation verification

The implementation retains the draft's identity claims, reservations, and four migrations. The repairs address three gaps: shared settings saves could rewind a concurrent allocation, unchecked settings fields could relocate the tenant/entity counter row, and the dev seed/label fixtures did not supply the now-mandatory tag claims.

The shared settings action now initializes with conflict-ignore, takes the same tenant/entity advisory lock as `generate_next_number`, and validates the current counter before saving. Runtime field validation rejects caller-supplied tenant/entity fields before any query. An empty settings save succeeds without an empty SQL update. Fixed development fixture tags and IDs are retained, with their claims created before inserting their asset rows. Label fixtures use `prepareAssetIdentity` in the same transaction as insertion.

## Code review

| Acceptance | Concrete code and behavior |
| --- | --- |
| Tenant allocation, formatting, settings, preview | `shared/services/numberingService.ts` delegates issuance to `generate_next_number`; its existing advisory lock and tenant/entity settings row serialize allocation. `shared/services/assetNumbering.ts` separates `clientAssetPrefix`/`formatAssetTag` from numeric allocation. An unset client prefix produces only the padded shared number. `ASSET` defaults to five digits and initial value 1. `AssetNumberingSettings.tsx` composes the shared settings control, showing last-used/next preview and configurable padding. `getAssetSequenceContinuationReview` scans trailing numeric runs across all legacy prefix lengths and provides an advisory suggestion. Settings are applied explicitly. `previewNextNumber` only reads settings and never initializes or advances a counter. Gaps are documented. |
| Full Add and Quick Add | Both default to automatic tagging and send an empty tag only on creation in automatic mode. Manual mode passes the scanned tag unchanged. Full Add refreshes its preview after repeated saves; Quick Add clears successful intake and previews again when reopened. Update paths claim a new identity only when the submitted tag changes under normalization. Client, ownership, and prefix changes do not rewrite stored tags. Creation retains the submitted MSP/client ownership. |
| Persistence and legacy data | The claim primary key is `(tenant, normalized_tag)`. Generated asset keys and colocated foreign keys bind new assets to their own claim. Exact captured legacy bindings preserve original duplicates and blanks; holding claims keep duplicate tags occupied. The audit and tenant activation require reviewed reconciliation and recheck live duplicates without merging or renumbering assets. Matching removes boundary ASCII spaces and folds ASCII letters consistently in SQL and TypeScript; scan lookup uses the same normalization and asset authorization kernel. `nextAssetTag` skips claimed, reserved, manual, and legacy collisions. |
| Creation paths and integration identity | UI writes, REST, inbound webhooks, CSV/import and migration appliers, inventory delivery, Hudu, shared RMM/Level, Tactical RMM, and both NinjaOne implementations prepare identity before insertion. Provider IDs stay in provider fields and mappings. Existing ingestion updates omit physical tags. The Level mapper requests automatic numbering for discoveries. |
| Printing and next value | `LabelPrintDialog` exposes copies per asset, defaults to two, and expands subjects in stable adjacent order (`A,A,B,B`). Existing template/layout choices remain. Label view models read the persisted tag and encode that value in Code 128; they do not allocate. The print pipeline retains repeated subjects, applies normal asset authorization, and reads storage without changing the counter or claim tables. Reprinting uses the same stored identity. |

The new client prefix field is explicit. No suitable existing dedicated client-code field was found in the client interface or client schema migrations reviewed. Prefix validation permits up to ten ASCII letters, digits, or hyphens and prevents duplicate nonempty prefixes within a tenant.
