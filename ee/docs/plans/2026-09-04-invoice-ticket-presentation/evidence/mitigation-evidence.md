- Authenticated generation exposed another failure: the invoice API schema discarded the canonical client's `scheduleKey` and `periodKey`, causing an undefined-binding 500. Two stale transform tests were updated to the approved collection label and explicit user-selected sort keys.

## Shortcuts and limits

- Source clients/contracts/services/approved time, allowance usage, taxes and project configuration are synthetic SQL fixtures in the wired local database (port 5472). Existing catalog types/statuses are reused. Generation, transactions, recurring selection, cap math, persistence, model reads, export projection and PDF production services are real. No completed snapshot was inserted to bypass generation.
- The opt-in Vitest harness stubs `getSession`, `withAuth` and `getCurrentUser` to the synthetic internal user's identity. The authenticated HTTP test and browser UI/portal logins use actual authentication outside that process. Its short-lived API key is deactivated and foreign link deleted in `finally`.
- Source edits after invoicing use SQL because the normal UI locks invoiced records. Historical/corrupt link variants are intentional mutations of generated evidence inside rolled-back transactions. These are not backfills.
- The custom nested container/alias was save-action seeded; fresh UI edits and save/reopen are real. Canvas samples five rows; full preview/PDF contain the complete detail. Literal custom headings remain authored English rather than being automatically translated.
- The synthetic client admin/contact/role were created with SQL; no invitation was sent. For portal route inspection only, one synthetic generated draft's status and `finalized_at` were temporarily set, then restored. No finalization, delivery, payment or automatic export action was invoked. The ticket fixture's missing `entered_at` initially crashed its page; the source fixture was corrected and the route then retested.
- A local synthetic password appeared in a failed CLI exception during portal setup. Both affected synthetic credentials were rotated. Credentials and login command scripts are excluded from durable evidence; no production/customer credential was used.
- Browser control uses native clicks/types and DOM event dispatch for existing controls. No renderer rows, successful production responses, or snapshots were injected into the browser. Unsaved filter/group experiments were removed after capture.
- Build output is isolated from the live port-3967 dev output and retained outside the worktree. Warnings in unchanged scheduling/workflow modules and the test stub's duplicate cookie member are recorded, not suppressed. External accounting systems, invoice delivery and every portal permission combination were not tested.
