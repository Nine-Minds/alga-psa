# A 15-day co-managed Seat trial

## Offer and customer experience

A new or existing hosted AlgaPSA Pro MSP can try one client technician with one client, once per sponsor tenant. This gives both sides time to work a ticket together. The MSP chooses when to invite the technician. The free period begins on that technician’s first successful interactive sign-in and runs for 15 consecutive 24-hour periods. Preparing the client, sending or accepting an invitation, and converting the base Alga subscription each leave the clock alone.

Offer the pilot in the co-managed overview alongside the paid option and in eligible client Seat setup. Let the administrator select a client, a technician and the normal board scope. Show who can use the seat, when the clock starts, how the base subscription affects access, and the recurring price before the invitation. Show the exact local end date after activation, plus a clear action to keep the seat. Send the technician the usual scoped invitation. Make invitation delivery retryable from the pending state.

The proposed monthly price is **$9.99 per co-managed technician**. Product may choose $10 before launch. Display the configured recurring price and currency throughout. An authorized MSP administrator must explicitly approve using paid capacity or confirm a purchase. The deadline itself never creates a charge. When the pilot ends, the MSP retains the ticket, assignment history and authorship, and can restore the same technician by funding the seat.

This release covers hosted EE and the client **Seat** arrangement. Workspace arrangements and signed appliance licensing use different provisioning and access models. Existing paying MSPs may pilot an additional client who has no live arrangement. An existing paid allocation cannot be converted to a free one. Ending an activated pilot consumes the offer. Before first use, an admin may cancel and replace an unactivated invitation using the same sponsor claim and ordinary invitation revocation.

## Architecture

**Ownership and funding.** Use an EE tenant-scoped pilot record with a unique sponsor key, the bound client, arrangement/allocation and technician assignment, operation identity, activation/deadline and paid handoff facts. Use tenant-qualified keys and tenant-distributed migration conventions. Keep the consumed record when a client, assignment or arrangement is archived. An allocation's funding source is either this dedicated pilot or the ordinary paid pool. Represent that association once and carry it through the existing allocation reads. Pre-existing rows default to paid funding. Keep the paid Stripe quantity, base MSP user count, pool availability and invoice preview independent of pilot capacity. The pilot cannot fund a Workspace, a second assignment, or a general pool increase.

**State and clock.** A missing claim is available. Preparing binds the claim to one assignment. Only a final authenticated interactive session for that assignment can transition it to active. Gate the first authenticated Seat landing/request before serving data if the auth stack has no safe post-auth hook. Require a real technician session, completed MFA where applicable, and current base access. Under a sponsor-scoped transaction, set the timestamps once using the database clock. At the exclusive deadline access expires on the next server decision. Repeated sign-ins, resends, stale tokens, failed authentications, background jobs, API keys, impersonation and delayed callbacks cannot start or extend the interval. Converted and ended are terminal for pilot eligibility.

**Base subscription and authority.** An eligible canonical Alga trial and a paid base subscription both permit pilot use. Apply the earlier of the pilot deadline and the base access cutoff on each decision. If the base trial lapses, pause co-managed access. If base service returns within the original interval, serve the remaining time. Show both dates when the base cutoff is earlier. Use existing subscription ownership and authoritative trial-end data even when a status webhook is late. A zero purchased pool is valid for a pilot. Keep discovery, billing authority, operational setup permissions, client scope and seat subject classification distinct. Reuse the normal scoped Seat identity and existing board/project rules.

**Access and recovery.** Resolve effective funding for the bound assignment at server admission for UI, API, reads, writes and existing sessions. Keep a lapsed technician in the restricted Seat principal class. Preserve the arrangement, records and MSP access on expiry. Use current time at admission, so scheduler or analytics outages cannot prolong access. Ordinary paid seats continue to use their own commercial lapse rules. New business logic and schema belong under EE, with an inert CE host seam where needed.

**Conversion.** Let the admin explicitly select one available paid seat, or review the existing Stripe quote for the paid pool total needed to add one. Show the effective charge timing before confirmation, including for early conversion. If the base account must be upgraded first, return the admin to this pilot after that flow. Persist conversion intent with its sponsor, allocation, quoted quantity and durable purchase operation. On verified capacity, convert funding for the *existing* allocation atomically, even if the pilot expired during checkout. Serialize the seat claim with ordinary pool writers, reserving the incoming capacity for that intent before other allocations can consume it. Give up any claim on terminal payment failure or explicit cancellation. Enforce idempotency across callbacks, webhook retries and reconciliation, including a crash after payment. Payment without a valid handoff surfaces a recoverable paid seat in the sponsor’s pool. A checkout return or unrelated webhook alone cannot convert the pilot.

## Acceptance and launch decision

A hosted MSP with one base trial user and zero paid co-managed seats can invite one client technician, work a shared ticket, and explicitly keep or allow the seat to expire. The base seat count is one throughout. An existing subscriber can start later on identical terms. Concurrent invitations, session starts and conversions produce one pilot, one deadline and at most one paid seat increment. MSP history remains usable through expiry and reactivation. Confirm the configured monthly price ($9.99 proposed, $10 alternative) before enabling the offer.
