## Implemented behavior

- Images remain inline; PDFs, videos and supported storage file types use downloadable file blocks. No embedded PDF viewer or video player. Comment and ticket Documents associations persist together.
- All composition sessions track unclaimed uploads. Cancel waits for in-flight uploads, withdraws completed drafts, and keeps the editor open if withdrawal fails. Upload failures do not publish comments or send email. Drafts expire after 24 hours. The recurring sweep processes at most 100 expired drafts per tenant; exclusively owned documents and storage are removed, while shared documents/files are retained. Attached removed/deleted content stays as revoked history rather than being physically collected.
- Create/edit reconciles only same-tenant/ticket, actor-owned, unexpired drafts under locks. Removal, deletion, canceled scheduling and internal visibility revoke access. Edits and visibility changes do not resend previously delivered files. Scheduled attachments become public only at publication.
- Public initial publication selects only that comment's eligible documents, deduplicates inline CID images by document ID, and applies provider size/type limits. A one-hour signed fallback link explains the omitted file. Existing matching users can download directly; contacts without accounts verify a six-digit email code. Codes expire within ten minutes/the original link expiry, bind to an HttpOnly browser nonce, permit five attempts, and redeem once. Current authorization is checked before code delivery and again before bytes.
- Verification pages use same-origin referrers so native form POSTs work; downloads use no-referrer/no-store and attachment disposition. Portal file sizes are normalized from PostgreSQL bigint strings to prevent the global Documents page from crashing.
