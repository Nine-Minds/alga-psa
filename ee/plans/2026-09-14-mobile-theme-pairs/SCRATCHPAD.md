# Scratchpad — Mobile theme pairs

## Decisions

- **Tokens come from the server, not the binary.** The app ships only the Alga preset (its current look). Every other pair, and custom pairs, arrive as 15 seed tokens in the capabilities response. Rationale: custom pairs cannot be shipped, and shipping the nine presets would create a second copy to keep in sync.
- **Port the ramp maths, pin it with a fixture.** `mix`, `rampFromStops`, `brandRamp` are copied into the app (the mobile bundle cannot import `@alga-psa/tenancy`). A fixture generated from the web implementation guards against drift.
- **Status colours are not part of the pair.** On the web the pair blocks only emit background/card/border/text/primary/secondary/accent/sidebar/header/table variables; destructive/warning/success come from the base `:root`. Mobile mirrors that: fixed per mode, badge/toast backgrounds mixed with the pair's card colour.
- **Tenant-wide pair, per-user mode.** Same rule as the web. No per-user pair override on mobile.
- **Sign-in screens stay Alga** until capabilities load, to avoid showing a previous tenant's colours on a shared device. Open question 2 in the PRD.
- **Editor web view is in scope.** It is the one place a user reads long text, and it is white today even in dark mode.

## Discoveries

- Web pair catalog: `packages/tenancy/src/lib/themePairs.ts` (`THEME_PAIR_IDS`, `THEME_PAIRS` with labels and swatches).
- Seed presets and derivation: `packages/tenancy/src/lib/customTheme.ts` — `CUSTOM_THEME_TOKEN_KEYS` (15), `CUSTOM_THEME_PRESETS` (all 9 predefined pairs, light+dark), `generateCustomThemeStyles` → `modeBlock` (neutral ramp from surface/border/borderStrong/textMuted/textSecondary/textPrimary with dark-mode low-stop capping; `brandRamp` for primary/secondary/accent), `findInvalidCustomThemeTokens`, `validateCustomThemeContrast`.
- Presets are pinned to `server/src/app/globals.css` by an existing unit test, so presets are canonical for mobile.
- Tenant choice: `tenant_settings.settings.theme` → `packages/tenancy/src/lib/tenantTheme.ts` (`TenantTheme { pairId, customTheme? }`, `normalizeTenantTheme`), read by `getTenantThemeByTenantId` in `packages/tenancy/src/actions/tenant-actions/tenantThemeActions.ts`.
- Capabilities: route `server/src/app/api/v1/mobile/me/capabilities/route.ts` → `ApiMobileCapabilitiesController.getMyCapabilities` → `MobileCapabilitiesService`; OpenAPI in `server/src/lib/api/openapi/routes/mobileCapabilitiesV1.ts`. Response today is `{ features }`.
- Mobile theme layer: `ee/mobile/src/ui/themes.ts` (`Theme`, `lightTheme`, `darkTheme`, ramps imported from `ui/colors.ts`), `ee/mobile/src/ui/ThemeContext.tsx` (preference light/dark/system in secure storage key `alga.mobile.theme.preference`). `useThemePreference` exists but **nothing in Settings calls it** — the app always follows the OS today.
- Mobile capabilities: `ee/mobile/src/api/capabilities.ts` (`MyCapabilities { features }`), `ee/mobile/src/capabilities/CapabilitiesContext.tsx` (refresh on sign-in, resume, focus).
- Hex literals outside the theme file (24): `DocumentsSection.tsx` (8× `#fff` in the preview overlay), `ScanView.tsx` (3), `Avatar.tsx` (identity palette, keep), `tagColors.ts` (keep), `SignInScreen.tsx`, `MentionSuggestionList.tsx`, `MaterialsSection.tsx`.
- Editor: `ee/mobile/src/features/ticketRichText/generatedEditorHtml.ts` is generated by `scripts/generate-ticket-mobile-editor-html.mjs` (run by `npm run typecheck` and `npm test`); edit the generator source, not the output. Bridge in `features/ticketRichText/bridge.ts`.
- High contrast on the web also restyles chips, switches, placeholders and the editor paper via `html[data-theme-pair="high-contrast"]` rules in `globals.css` (around lines 146–195, 352, 2934–2949, 3173–3189).

| badge.* / toast.* | status colour mixed with card (ratios TBD during theme-engine group; record here) |

Unused seed tokens on mobile: surface (only feeds the neutral ramp), sidebarBg, sidebarText, sidebarHover, headerBg.

### Badge / toast mix ratios (decided in theme-engine)

`STATUS_MIX` in `ui/themes.ts`, measured so every tone clears 4.5:1 on every pair:

| Mode | bg (card → status) | border (card → status) | text (status → black/white) |
|---|---|---|---|
| light | 0.16 | 0.45 | 0.45 toward black |
| dark | 0.26 | 0.45 | 0.60 toward white |

Neutral badges skip the mix and use the neutral ramp: bg 100, border 200, text 700 (light) / 600 (dark). `toast.info` is the plain card (bg card, border border, text textPrimary), which is what the hand-written themes did; `toast.success` / `toast.error` reuse the success and danger badge sets.

Lowest measured badge label contrast across 9 pairs × 2 modes: 4.87 (high-contrast light, neutral).

### textInverse deviation from FR7

FR7 says "white when the primary is dark enough for 4.5:1, else textPrimary". Taken literally that makes dark pairs *worse*: their `textPrimary` is a near-white, so Forest dark went from 3.29:1 (white) to 2.85:1. Implemented rule: white when it reaches 4.5:1, otherwise whichever of white / textPrimary reads better — the web validates its own button labels at 3:1, and every pair clears that (worst case Forest dark 3.3:1).

## Gotchas

- `server/.env.local` may pin the edition to `community`; custom pairs are Enterprise-only, so test the custom path against an EE-configured server.
- The device shows the native shell version, not `app.json`; a JS-only change like this one ships through the normal bundle, no native rebuild.
- Secure storage reads are async; the "no purple frame on warm launch" requirement needs the cached block read before `NavigationContainer` renders (AppRoot already gates on `navStateLoaded`; add the theme read to the same gate).
- Keep `lightTheme`/`darkTheme` exports: ~150 files import `useTheme` but a handful of tests import the objects directly.
